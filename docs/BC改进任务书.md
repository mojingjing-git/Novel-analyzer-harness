# 小说分析器 B/C 改进任务书

版本：1.0  
日期：2026-11-05  
状态：待执行。本文件定义下一阶段工作，不表示任务已经实施。  
主目标：在跨作品可复用、成本可控的前提下，减少漏项，并防止无依据答案进入最终结果。

## 一、阶段判断与工作优先级

**本阶段以 B 类遗漏定位和修复为主线，C 类按需审核为次线。** 优先处理能够跨作品复现的数据丢失、取材遗漏和判断链路问题。

|问题|本任务中的定义|当前状态|
|---|---|---|
|B：漏项|原文存在应登记的问题或足以支持某项回答的证据，但相应信息没有进入应有产物|原文盲读、抽样与曝光记录工具已具备；尚无召回改善结论|
|C：不可靠判断|候选答案扩写、错配对象、混淆计划与完成、把人物说法当作已证实事实，或不满足关闭条件却被接受|第二版逐项证据协议已实现，默认关闭；开发样本有改善，保留作品检查未显示额外准确性收益|

最近一次保留作品检查：4部小说、8条构造题，两种方法均匹配参考标签；第二版总token增加约30.6%，平均请求耗时约1.43倍。参考标签由模型辅助复核，不能当成人工金标准或自然错误率。最近一次全量测试为1997项通过。

依据：[第二版保留作品报告](research/bc-cross-work-2026-11-05/v2-holdout-report.md)。

## 二、范围与约束

本阶段交付：遗漏追踪、原文先行的B评测集、针对主要根因的修复、C按需审核实验、质量与成本对照报告。

本阶段不承担界面重做、引擎整体迁移或全书分析算法重写；不预设必须换更大模型。所有评测使用独立输出目录，保留原始小说、生产账本、历史结果和旧标签。

- 完整记录与送入模型的上下文视图分开处理。控制提示词长度不能导致原始条目静默消失。
- 不重切已经分析的生产工作区。需要新切分时，在独立副本中进行并保存来源映射。
- 通用层保持标准库依赖；沿用既有引擎边界，不引入反向数据层依赖。
- 不打印、复制或提交运行密钥。异常日志沿用项目脱敏机制。
- 不为某个人名、书名、具体剧情或个别评测答案写专用规则。

## 三、任务包与交付物

### T0｜冻结基线与评测范围（P0）

盘点当前生产链路、实际模型配置和已有产物，明确哪些结果可重放、哪些需要重新运行。冻结源码、提示词、来源文件、运行参数、预算与比较方法；不得将不相同输入的旧输出拼成配对基线。

所有已经用于调试的作品登记为已曝光，包括道诡异仙、大奉打更人、三侠五义，以及上一阶段选出的8部作品。新目录为 `F:\AI\04_小说与写作\修复后txt文件`。

**交付**：运行声明、曝光登记、基线清单、模型调用预算。

**完成条件**：可以根据清单定位同一源码、同一输入、同一配置与同一结果；不存在被重新标为“未见作品”的旧样本。

### T1｜建立 B 类遗漏追踪（P0）

围绕真实分析链路串联原文、模型原始输出、解析结果、合并/账本、取材、判定、持久化和最终展示。每个被保留、合并、排除、截断或跳过的条目都应有去向和原因。

|分类|识别依据|需要保留的证据|
|---|---|---|
|B1 未登记|独立原文标注存在，而模型输出或登记结果不存在|原文位置、期望登记内容、对应原始输出及解析情况|
|B2 未取到证据|条目已登记，允许搜索范围内有答案证据，但检索未返回|搜索范围、检索输入、候选排序、实际送审原文|
|B3 判断漏掉|证据已送审，模型或合成规则仍漏报有效回答|完整问题与条件、送审证据、原始响应、最终判定理由|
|B4 流转丢失|内容曾存在，随后在合并、裁剪、落账或展示中消失|丢失前后快照、处理规则、来源条目与目标条目映射|

这四类是归因类别，不代表固定执行顺序。记录首次可证实的丢失点及后续影响；无法确定的标为“未定位”，不得根据最终缺失反推模型没有发现。

追踪最少包含：运行ID、来源指纹、原文坐标、参考观察ID、条目ID（尚未登记时允许为空）、阶段、处理前后状态、原因码、相关产物位置、耗时与调用统计。

**交付**：追踪记录格式、链路接入、遗漏归因报告。

**完成条件**：冻结范围内每个已确认遗漏均能定位到上述类别或明确的未定位原因；所有主动丢弃都有可审计记录；关闭追踪时业务结果保持一致。

### T2｜建立原文先行的 B 评测集（P0）

先由标注者阅读原文，记录应登记的问题、局部回答及其证据，再对照分析器输出。标注阶段不可查看待测候选或最终判定。模型提案必须保留来源，独立复核后才进入相应参考集合。

两类参考项分开统计：

- **登记项**：当前原文足以支持其作为待跟踪问题被登记。
- **回答项**：已有明确问题与关闭条件，允许查看的原文中存在足以支持回答的证据。

尚无答案的伏笔不计为“回答遗漏”。只能确认部分信息的项目不标为整条关闭。跨窗口背景不足、存在争议或无法定位的项目单列，报告数量和占比，不能靠排除难例美化分数。

新一轮至少按整本隔离4部开发作品与4部保留作品，覆盖至少4个预设题材组。先按书目确定分组，再固定抽样；同书改名、版本和近重复文本不得跨组。既有已曝光作品可以补充回归测试，不能充当新保留集。

窗口、连续章节区间、前情快照及允许检索范围必须固定。局部区间测试只报告局部覆盖；全书召回结论必须来自完整全书链路。若只能跑局部链路，要明确缺少哪些全书状态。

**交付**：盲读包、参考观察清单、标注与分歧记录、冻结版本、真实产物对照表。

**完成条件**：每项都有逐字证据和来源位置；标签冻结早于待测结果；分母不依赖分析器是否发现该项。最终保留集建议至少80条可裁决参考观察、每书至少10条，登记与回答项分别列数；不足时报告证据不足，不换有利样本补齐。

### T3｜修复最主要的 B 根因（P0）

根据T1/T2的证据排序，优先修复跨作品复现、影响面大且成本低的原因。首批集中处理不超过两类主要根因，逐项比较，保留单项开关或可重放的改动对照。

可能的修复方向，以实际诊断为准：

- 若完整记录被容量上限覆盖：保留完整存储，仅对模型视图做预算裁剪，记录未进入本轮上下文的条目。
- 若证据取材不全：改善候选检索和邻近上下文补取，并记录搜索边界；无法判断时保留未确认状态。
- 若关闭条件、引用或对象错配：沿用共享条件与来源绑定，修复具体流转错误。
- 若原始输出已有信息而解析/合并丢失：修复转换和映射，补充可重放的边界回归。

**交付**：修复代码、失败案例回放、针对根因的测试、分作品对照与成本记录。

**完成条件**：每项修复说明作用环节，并在至少两部开发作品复现原问题和修复效果；新保留集上按预登记标准验证。若根因不能证实，不提交仅为提高考卷分数的规则。

### T4｜评估 C 类按需审核（P1）

在B链路稳定后，从真实候选分布采样，不再只依赖构造正负例。比较现有验收、全量第二版、按需第二版三种策略。

按需策略只能使用判定当时已知的信息，例如答案片段数、关闭条件结构、指代/阶段变化和基础验收的不确定信号；不能读取参考标签或未来结果。触发规则必须在打开最终保留结果前冻结。

对触发与未触发部分均独立抽查，单列“未触发却误接受”的数量。必要时复用相同输入与配置的已冻结调用结果，但必须标明重放；实际端到端耗时需实测，不用重放时间代替。

**交付**：默认关闭的选择策略、触发记录、至少80条真实候选的对照、漏触发与成本分析。分层采样需报告分层占比，不能把人为平衡的样本当作自然错误率。

**完成条件**：能解释每次额外审核为何触发；拒绝、存疑、格式失败和语义误判分别统计；额外调用带来的收益与成本可计算。未显示收益时维持可选模式。

## 四、统一指标与验收门槛

以下数值是本任务建议采用的工程目标，不是已有测量结果。执行者应在T0锁定；看到最终结果后不得放宽。

|维度|统计口径|建议验收标准|
|---|---|---|
|B登记覆盖|正确登记的参考登记项 / 可裁决参考登记项|分作品报告，和回答覆盖分开|
|B回答覆盖|正确识别的参考回答项 / 可裁决参考回答项|修复所针对的B指标，相对遗漏数减少至少20%；至少3/4保留作品不退化，至少2部有改善|
|C误接受|被接受的不支持参考项 / 不支持参考项|同一配对集上不增加，同时报告误接受的原始数量|
|正确项保留|被接受的支持参考项 / 支持参考项|下降不超过2个百分点；存疑不能算保留|
|判定覆盖|非存疑项 / 全部评测项|必须随准确性指标一起报告，防止靠全部存疑通过验收|
|证据与格式|来源有效、完整覆盖、格式失败分别计数|引用未定位或必要字段缺失不能自动通过；格式拦截不能算语义识别成功|
|资源开销|同范围总token、逻辑调用、实际尝试、端到端耗时、峰值内存|拟默认启用的组合方案，总token增幅≤15%，端到端P95耗时增幅≤20%|
|工程正确性|相关回归、全量后端与必要前端检查|后端T3通过；涉及前端时完成构建和相应测试|

零分母记为N/A。基线没有遗漏时不能声称相对减少20%，应报告该子集未能验证增益。所有指标保留分子分母、逐书差异与争议率；小样本上的工程达标不等于统计意义上的普遍提升。

工程完成、效果达标、适合默认启用分别作结论。效果或成本不达标，可以交付诊断结果与默认关闭的能力，不得标为整体优化成功。缺少可靠独立复核时，结论明确保留为模型辅助评测。

## 五、执行顺序与分工

|里程碑|内容|进入下一步的条件|
|---|---|---|
|M0|T0基线、书目、参数与预算冻结|来源和曝光状态可追溯，预登记完成|
|M1|T1追踪、T2开发集标注|已确认主要遗漏类别，参考项不依赖候选生成|
|M2|T3修复与开发回归|跨至少两部作品复现；没有用格式失败制造收益|
|M3|T4策略开发，冻结最终版本|方法、参数、样本、预算和指标均锁定|
|M4|一次性保留集检查与报告|保存全部结果；不依据这轮结果改题重跑|

主代理负责链路诊断、实现、集成和最终归因。Luna负责有界的原文盲读提案及引用核对；不独自认证自己生成的参考标签。复核者先处理原文和分歧，再接触待测结果。各方写入范围分开，避免共同改动冻结产物。

首轮默认逻辑调用上限建议300次、实际请求尝试上限400次、并发上限2；在M0按真实链路分配到各阶段，并冻结各类调用的上下文与输出预算。完整运行所需预算超限时，交付已有证据和未覆盖范围，记录新一轮计划，不静默截上下文、降低分母或无限重试。原文审读、程序重放和无模型测试优先复用已有材料。

## 六、停止条件

- 来源、代码、提示词或标签发生变更：本次运行失效，保留原记录，生成明确的新版本。
- 保留作品被用于调参：记为已曝光，后续只能作为开发材料。
- 发现收益仅来自更高拒答率、格式错误或标签移动：暂停效果宣称，分别定位原因。
- 达到预算上限、持续出现调用失败、或上下文不足以判断：保存结果并列出缺口，不补选容易样本。
- 同一问题在开发集连续两轮没有可解释改善：回到根因和证据表示检查，避免继续追加样本专用提示。
