# 证据归因与格式恢复独立复核

日期：2026-11-06。范围：当前工作区实现、既有曝光案例和离线回放；未调用线上模型，未改生产代码或历史报告。

## 结论

提示词哈希核验是有效进展；格式失败限次重试、语义拒绝不重试和失败缓存不复用的方向成立。但不能据现有结果直接把 hist/fs_011 定性成应向前放宽的检索错误，也不能把恢复 answer_ok 等同最终通过。建议先修复解析器边界、校正归因，再做区分背景与后续揭晓的检索原型。C 默认值保持不变。

## 1. 高优先级：本地格式修复并非只修改闭合符

位置：`backend/common/c_claim_audit_gate.py:219-233,237-258,288-310`。

修复器依次尝试将字符串外所有右圆括号替换为方括号、花括号或删除；随后用 raw_decode 读取首个对象而不检查剩余内容。已离线复现：

```text
输入：{"verdict":"answer_ok","criteria_satisfied":tru)e}
输出：{'verdict': 'answer_ok', 'criteria_satisfied': True}

输入：{"verdict":"answer_ok","criteria_satisfied":true,"answer_supported":true),"verdict":"off_topic"}
输出：{'verdict': 'answer_ok', 'criteria_satisfied': True, 'answer_supported': True}
```

第一例修改了布尔值词元；第二例提前闭合对象并忽略其余裁决内容。非法字符存在，并不能证明其删除或替换只有唯一解释。这些是解析行为反例，不声称实际历史调用发生了上述误接受。

建议：只在括号栈明确期待闭合符、前一个完整值已结束的位置允许有限修复；禁止修补字段名、字符串和布尔/数字/null 词元；修复后完整消费对象内容，拒绝有意义的尾部和重复键，保留原文及修复记录。无法唯一修复时走预算内重试。现有新增测试的“数组闭合错误”样例实际是在完整对象后追加右圆括号，原先 raw_decode 已能读出，不能代替真实嵌套数组错误及拒绝边界测试。

## 2. 高优先级：检索不对称有明确时间边界，不能直接拉齐证据包

独立调用 rebuild 得到：

|案例（candidate 臂）|登记章|重建证据章|字符数|历史提示词哈希匹配|
|---|---:|---|---:|---|
|hist/fs_006|5|5、11、10、9|3255|否|
|hist/fs_007|7|7、9、8、10|2685|否|
|hist/fs_011|12|12|822|是|
|game/fs_003|6|6、7、8、10|3268|是|

hist 第11章确实包含“勾结金人”“搬三山”“扳倒三衙禁军”。但 fs_011 登记在第12章；`backend/core/evidence.py:315-322` 明确只选登记章之后的命中和提名章节。这解释了为何它与第5章登记的 fs_006 不同。同主题不代表相同登记时间、问题或可计入回收的证据范围。

需要分开处理：登记前材料作为背景，登记后的新信息作为回收候选；同章还需比较原文位置。可进一步查登记是否滞后、锚点是否选错、审核是否缺少必要背景，但不能仅因补入第11章后能够支持答案，就称其为后续回收改善。

fs_006 的3255字重建未通过历史哈希核验，不能拿它宣称同臂历史审核一定收到了相应完整四段；3265字是其他臂的当前重建值，也未经历史哈希验证。

## 3. 重要：fs_007 归因仍待输入证据，关键词命中不能替代语义裁决

`scripts/bc_t4_evidence_attribution.py:125-137` 在哈希未匹配时用审核自身引用作为输入证明。模型引用一句话不能证明它没看到其他句子，也不能证明引用一定来自请求。fs_007 应保留为未核实，不能写成已证实未送达。

哈希匹配可以确认重建提示词与记录的提示词一致；它本身不证明选定几个词是答案成立的必要充分条件。脚本 KEY_SENTENCES 实际含大量关键词，不能以缺一个词自动判“证据未送达”。应分别记录精确原文跨度是否存在、语义支持是否足够。

初始复检请求未缓存的部分仍应保持未知。结案表中 baseline 4条、b_fixed 2条等归因到召回的统计应同步撤回或标为假设。当前可以说“已证实局部审核材料缺少指定支撑句”，尚不能说“已证实全链路最大瓶颈”。“确认的审核误杀案例为0”也不等于误杀风险为0。

## 4. 重要：game/fs_003 恢复输出后仍未通过完整门禁

将哈希匹配的重建审核输入及历史原始响应送入当前 extract_json_object 和 gate，结果为：

```json
{"matched":true,"raw_verdict":"answer_ok","gate_decision":"存疑","reasons":["待复核：evidence_not_after_anchor"],"assessment":"unconfirmed","claim_errors":[],"claim_blockers":[]}
```

因此可证明的是恢复了解析后的模型裁决；还不能报告为恢复一条最终通过或提升生产保留率。需定位证据章字段与同章先后判定，不应为了让该例通过而直接删除时间边界。

## 5. 次要工程问题：重试记录不完整

`backend/services/recheck_v2.py:1044-1057,1073-1083,1163-1172`：重试覆盖 sec；成功缓存仍写 attempts=1；重试异常最终统一写 INVALID_FORMAT，未保留异常原因；双次格式失败缓存只存初次原文。全局调用计数有递增，但这些单请求缓存字段无法完整复核尝试次数、耗时和失败路径。建议逐尝试保留记录并累计耗时，分别保存格式错误与调用异常。
