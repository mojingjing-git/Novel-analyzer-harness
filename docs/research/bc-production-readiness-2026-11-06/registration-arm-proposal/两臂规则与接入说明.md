# 登记位置规则对照

状态：模板与运行器的离线部件已就绪，**尚未接入模型调用器或生产分析器**，未调用模型。
规则版本 registration_anchor_ab_v1。

## 已确认的现状

生产提示词 backend/core/prompt_builder.py:51 要求模型摘一句能支撑伏笔的原文；backend/core/analyzer.py:238-250 调用 verify_result_anchors；backend/core/anchor.py 检查逐字或忽略空白的存在性并映射章节。现有校验并不证明读到该位置时问题已经成立。

## 两臂唯一的提示词差异

- A：相关摘句规则。取一句能支撑伏笔的原文。
- B：在A之后追加“读到所选引文末尾时，提出该问题所需的信息应已齐备；在合格位置中选最早一句”。

B不是取关键词首次出现，也不是根据后文答案往前找。它可能更少提出无据问题，也可能过度保守而漏登记；两种结果都要计入。提示词要求不等于已验证模型遵守，合格跨度仍由只见相应前缀的独立裁决检查。

## 这是什么对照

这是现有锚点规则的登记任务投影与候选规则的对照，不是原样完整生产baseline。两臂共同抽出生产提示词的伏笔相关要求，使用相同的简化输出，省略人物弧光、地点、其他分析和50类分类。因此不能把其差异直接解释为整本生产管线改善。

共同提示词还明确了“截至当前前缀仍未解”；这条同时作用于A、B，不能把它的收益归因给B。若后续验证完整生产效果，应把同一B附加规则接回完整生产提示词，保持其他字段、上下文和预算一致另行测量。

## 确定性装配

- system消息：common-system.txt 原文 + 两个换行 + 对应arm规则文件原文。
- user消息：common-user-template.txt 替换任务字段和完整原文单元。两臂同一任务的user消息逐字一致。替换仅处理模板占位符，不对插入原文再次做模板展开。
- 同一任务的模型、采样参数、输出上限、原文、提示包装、重试规则、定位器与指标一致。规则长度不同造成的输入token差异应实记，不要求虚假的费用相同。
- 首轮摘要、知识库、检索材料显式unused，仅正文前缀进入任务；两个生成器分别用干净会话。模型调用顺序在前缀间交替A/B，记录采样参数，但单次生成仍有随机性，不作显著性结论。
- 模型只输出source_unit_id和引文，由同一个宿主定位器在声明单元原文中得到唯一[start,end)；歧义、越界或不匹配单列，不默取第一个命中。输出的精确跨度、item_id、prefix_id、冻结信息由宿主追加，不改变模型原始响应。
- 解析/接口结构损坏按预算规则处理；原文不支持、位置不合格是质量结果，不以“格式重试”名义重新生成。截断则整个任务标incomplete。

## 保持观察时点真实

两臂的登记检查点均为本次实际可见范围终点。选中更早引文不代表更早登记。

每个前缀独立生成，不把后一个前缀的输出回填前一个。登记延迟以该问题在哪个实际检查点首次被系统提出为准；跨检查点的语义身份对应若无独立配对，标unresolved，不用mother词或文字相似直接当作同一问题。首轮配对预算不足时暂不报告延迟，不额外偷偷增加调用。

## 参考与盲审

参考标注者不看A/B规则、系统输出或后文；先自主发现问题并冻结可接受跨度集合。盲审用共同协议，不将B的措辞当成标准答案。

由于提示规则可能同时改变提出的问题集合，分别报告：
1. 全部输出的无据率、已答仍登记率、有效裁决覆盖率、相对独立参考集遗漏；
2. 两臂经独立判为同一问题的配对子集，其锚点合格性与实际登记检查点；
3. 仅一臂提出的问题及争议。不得只挑交集就宣称总体改善。

不能只看平均锚点变早、条目变少或通过率升高。六个前缀嵌套在两部作品中，彼此不是六个独立作品样本，首轮只作方向与成本检查。

## 参考标注的产出格式

模型标注与人工标注**共用同一份格式**——校验、合并、冻结、匹配只认字段，不认来源。
人的盲点与模型的盲点一样存在，不能仅凭"人标"就当成真值。

每条标注至少包含：

| 字段 | 说明 |
|---|---|
| `question` | 具体未解问题 |
| `answer_criteria` | 可接受的回答条件 |
| `supporting_quote` | 支撑引文 |
| `acceptable_spans` | 可接受跨度集合（`unit_id` + `[start, end)`） |
| `label` | `有依据且未解` / `已经回答` / `无法确定` |
| `reason` | 简短理由 |

整份标注还必须记录：作品、前缀、标注者、协议版本、
**实际看过的范围**、是否完成、完成时间、冻结哈希。

**发现阶段不得填写 `registered`**——那是盲审对照系统输出后才确定的字段，
填了会被校验直接判不合格。匹配结果必须**分别记录 A、B 两臂**；
语义配对失败标 `unresolved`，**不默认为漏登记**。

## 流程

两份独立发现 → 合并去重、保留争议 → 冻结参考集 → 运行两臂 → 盲审匹配。

合并规则：逐字同题且判断一致 → 合并为 `agreed`；同一题判断不同 → `disputed`
（两方意见都保留，标签记 `无法确定`）；同引文但措辞不同 → 标 `possible_duplicate`
**不自动合并**；只有一方提到 → `single_annotator`。

冻结后拒绝原位覆盖，修订另建版本。

## 参考计分的连接

参考条目有**独立的资格状态**，与原始标注分开记录：

- 合并阶段**一律待裁决**——没有任何条目自动进入合格集合。
  同题同标签也**不自动**视为回答条件一致：两边原始条件与跨度都保留，
  由裁决时逐条对照。
- `apply_qualification` 产出**用于计分的合格参考集**：只有已确认
  "有依据且未解"、完成去重与条件裁决的条目进入 `eligible`。
- `disputed`、`single_annotator`、"已经回答"一律不进；
  未做裁决的保持待裁决，也不进。
- **原始标注冻结与计分用合格参考集冻结分开记录**，各带哈希。

盲审匹配按臂分别统计，规则是：

| 情形 | 判定 |
|---|---|
| 没有配对记录 | **unresolved**（不是漏登记） |
| 同一 ref_id 的配对记录冲突 | unresolved |
| 配对值非法 | unresolved |
| `matched=True` 但未绑定 `system_item_id` | unresolved |
| `matched=True` 但绑定的 id 不存在 | unresolved |
| 明确的 `matched=False` | **漏登记** |

`to_metric_inputs` 直接从匹配结果生成指标输入，`registered` 不由调用方手填——
未确认的参考无法通过下游 schema 转换重新进入分母。

## 长度预检

初筛的字符比例估算**不能证明**不超上限。本地没有与端点匹配的词表，
因此按端点实测标定：参考发现请求实测 **4371 非 ASCII + 1127 ASCII 字符
→ 7675 输入 token**，即非 ASCII 约 1.69 token/字符。

预检用 `conservative_token_bound`（非 ASCII 系数 1.75、ASCII 0.30、开销 16），
是**上界**。每次发送前按**完整请求**检查——包括盲审阶段送入的参考条目、
跨度摘录与两臂输出。超限则任务未完成，不隐藏截断、不忽略条目、
不临时放宽预算。

按此标定，2、3 物理单元的前缀单请求需 11 000–17 500 token。经 2026-11-07 裁决，单请求输入上限放宽至 **20000**；但总预算硬上限（42 次调用、336000 输入、84000 输出、并发 2）保持不变。
**注意**：之前“总量够用、代价为零”已纠正。6 前缀参考与生成占约 295029 token，留给盲审与重试的仅剩 40971 token，6 次盲审平均仅约 6829 token，尚无重试余量，**完整六前缀能否跑完仍未证明**。

### 输入包哈希的约定问题

复核方声明的 `input_package_sha256` **无法复现**——穷举顶层键组合与多种
序列化形式都对不上，说明复核方用了自己的哈希约定。
这是**约定不可复现**，不是"拿错了包"。

已改两处：包内新增 `package_sha256_canonical` 字段，复核方**直接引用**即可，
不必自己重新序列化；核验同时用**逐字内容绑定**兜底——每处接受跨度都逐字
落在原文上、且都出自原始标注给出的跨度，引文与跨度逐字一致。
本次裁决的内容绑定核验通过（3 处跨度）。

## 独立复核的分工与裁决包

参考集的独立复核与争议裁决由复核方负责，执行方不逐条审。

裁决包已按前缀生成（`adjudication-packages/`），每个包**只含**：

- 该前缀的**可见**原文单元；
- 合并后的标注条目（含**双方**原始条件与跨度）；
- 复核协议、检查项与期望输出格式。

**不含**：前缀之后的原文、两臂输出、任何答案或回收标签。
包内单元哈希与选片清单核对一致（不一致即中止），并已验证包内文本
恰好等于可见前缀、不含后文片段。

复核方应在**只提供该包的隔离上下文**中工作，避免其上下文里已有的后文信息
影响判断；保留每条理由供抽查。

复核者类型在记录中如实标为 `ai_independent_review`——**AI 独立复核，
不冒称人工标注**。

裁决输出经 `validate_adjudication` 校验：未知 ref_id、缺理由、
`qualified` 但标签不是"有依据且未解"、合格却缺回答条件或非法跨度，一律不合格。
未裁决的 ref_id 保持待裁决，不进合格集合。

**回答条件不同不能机械取并集**：那会把双方要求叠加、重新制造过严的关闭条件。
按原文判断哪些要求成立——等价的要求归并成一条，互补且各自必要的保留为多条，
无法确定的保持争议。

## 首轮标注方式与预算影响

首轮建议**两份独立模型标注 + 人工处理争议**：不必让全部阅读由人工承担，
也能检查模型之间的共同遗漏。

若全部改用人工，模型调用上限可从 42 降到 30（省去 12 次参考发现），
但**阅读与仲裁的人力成本仍需记录**——人工不是零成本方案。

抽取式辅助材料可作为本轮简化约束，不应推广成“改写摘要永远不能证明来源”。受控地仅用前缀生成并记录完整生成链的摘要也可研究；反过来，原文摘抄若由看过后文的选择器挑选，选择过程仍可能泄露信息。本轮全部unused，避免引入该变量。
