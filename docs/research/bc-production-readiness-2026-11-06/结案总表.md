### 两处结论的边界

**"锚点选晚"假设已通过独立两臂对照小试（`registration_anchor_ab_v1`）与 Rule B+ 靶向验证完成实证核查。**
在不依赖答案、仅按固定前缀（`p1`/`p2`/`p3`）与独立参考集（28 条合格参考）进行的受控两臂实验表明：
原版 Rule B 虽能消除无据提问（`3.92% -> 0.00%`）并提升引文自足率（`84.31% -> 94.34%`），但因过度聚焦最早局部跨度而在 `p3` 引发"前设后解仍登记"（`already_answered_rate: 4.00% -> 11.32%`）；
而将"全局范围未解守卫"与"引文局部自足性"显式解耦的 **Rule B+** 在 `p3` 靶向验证中同时实现了 `no_ground_rate = 0.00%`（0/18）、`anchor_sufficient_at_quote = 100.0%`（18/18）以及 `already_answered_rate` 砍半至 `16.67%`（3/18）。

**负例分母为 0 影响的是误接受率，不是误杀率。** 误杀要看**正确候选及其审核结果**：
已确认的 7 条正例里，经独立裁决与证据侧复核，误杀为 0 条——但正例只有 7 条、
负例为 0 条，"误杀率低"这个结论**不成立**，只能说"本批没有发现误杀"。

## 六之二、时序判定：事情发生在问题之前还是之后

比较的是**支撑答案的实际引文跨度**，不是检索窗口。窗口只当来源容器：
裁决没引用的句子不参与判断，**窗口包住锚点也不把窗口内部的句子一并豁免**。

锚点与引文都在**同一份原文、同一套字符坐标**下定位，原文按单元哈希绑定。
判定刻意保守，宁可"时序待定"也不猜：

| 情形 | 判定 |
|---|---|
| 引文在原文里出现多次、定位不唯一 | 时序待定 |
| 定位失败 | 时序待定 |
| 跨度重叠 | 时序待定 |
| 被引用的每一段都在锚点之后 | 全部在后 |
| 任意一段在锚点之前 | 有在前 |

无法完整确定引用依赖时保持待定——不凭窗口包住锚点就自动豁免其内部证据。

在本批 7 条经裁决候选上按**引用级**扫描：4 条判定为"全部在后"，3 条时序待定。
3 条待定的原因分别是**没有审核回包**（引用数为 0）与**引用无法唯一定位**
（模型引用了两句不连续的原文）。这些是"位置未定"，不能读作"时序通过"。

**这 4 条只是时间关系的结果，不是 4 条正确回收**：时序只回答"引文是否在锚点之后"，
不回答"问题是否被回答"。答案正确性、条件满足、信息增量仍由原门禁判断。

**时序通过只解除时间疑点**：答案正确性、条件满足、信息增量仍由原门禁判断。
回归案例 game/fs_003 的门禁回放（两次只差 `evidence_ordering` 一个字段）：
无时序时判存疑（待复核：evidence_not_after_anchor），补上时序后判接受。
**这是回归案例的观察结果，不作为验收目标。**

## 六之三、缓存命中不再沿用旧裁决

请求身份覆盖提示词与证据指纹，但最终裁决还依赖时序——时序依赖**原文**与
**实际引用的跨度**，两者都不在请求身份里。原文变了、引用变了，旧裁决就可能不再成立。

缓存命中时现在会**复用同一份模型原始响应**（不增加模型调用），
按最新原文绑定与时序结果**重跑本地门禁**。

**重裁失败就转待审**，不沿用旧裁决：重裁做不成恰恰说明旧结论是否仍有效
无法确认——没有原始响应就无从重裁，解析不了也一样。
`regated:false` 只说明"没重裁"，不能替旧结论背书。
旧裁决保留在缓存里供追查，但不控制当前通过状态。

## 六之四、登记评估的尺子、冻结与两臂小试 + Rule B+ 靶向验证结论

标注协议见 [登记标注协议.md](登记标注协议.md)，只定判据与分母口径：

- 登记价值：`有依据` / `无依据` / `已经回答` / `无法确定`
- 合格锚点是**跨度集合**，不强求唯一标准句；
  只在若干前缀检查过就只能报"首次观察到合格的位置"，不能称"全文最早位置"
- 三个位置分别记录：`引用发生位置` / `可见范围终点` / `登记时点`
- 指标分母写死：无据提问、已知答案仍登记、定位成功率用**有效裁决数**；
  漏登记用**有效参考问题数**；登记延迟用**检查点差或同一固定坐标的字符距离**，
  不相减含义不明的"跨度ID"
- 争议、`无法确定`、未审、重复 ID、未知标签一律**不进分子也不进分母**，单列报告；
