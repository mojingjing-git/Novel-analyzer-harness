## 为什么不能宣布效果提升

1. **那条“少放过的错误”并非被语义识别出来。** 历史负例把指令改成已完成，两种提示都把它判为有依据。claims_v1 恰好在划分答案时漏了分号，程序因完整覆盖失败转存疑。它防止了本次放行，但不证明模型学会区分“下令”和“办成”；如果只自动修补这个标点而保持原语义声明，错误就仍可能放行。因此保留原始结果，不以0/4误放宣称提升。
2. **单一类别混合了两条轴。** 工业正例保留了“后续计划”，模型把答案标为 planned、证据标为 attributed。这两种性质可以同时存在，严格相等核对压住了一个忠实答案。current 同样未保留此正例，但原因是误认为“后续计划”没有说明执行状态。
3. **格式负担本身不稳定。** 8条逐项响应有3条没逐字覆盖完整答案，主要漏标点。结构门禁和语义正确率必须分开统计，不能用更高的格式失败率制造更好的阻止通过率。

据此保持 `--claim-audit` 默认关闭，不更新生产账本。后续值得验证的是：分别表示“谁在断言”“说的是事实/计划/假设”“实现到了哪一步”，以及由程序提供固定答案片段编号，让模型对编号取证，减少反复抄写全文造成的格式失败。这是下一版待测方向，本轮没有针对这8题调参后重新包装成验证收益。
