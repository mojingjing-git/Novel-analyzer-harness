# 复检 V2 首轮真书实测（2026-10-31）

## 结论先说

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 锚点命中率 | **8/8 = 100%** | 2 章、8 条伏笔，模型的每条引文都在原文里逐字找到 |
| 账本候选 | 8 条，全部带锚点 | 锚点确实进了账本 |
| 复检覆盖 | 8 条中核对 2 条 | 这是**我给的预算上限**所限（`--max-calls 4`），不是能力上限 |
| 判定分布 | 证据不足 2 / 冲突 0 / 支持 0 | 两条都是 `INSUFFICIENT`，即"查了，但当年的埋设原文不足以判定" |
| 状态 | `RUNNING`（存在未核对候选） | 诚实标注，不是"完成" |

**这两个数字说明什么**：锚点这条链是通的（100% 可定位），而复检在预算受限时会把没查完的
明确标成"未核对"，而不是拿模型自述凑数。

**这两个数字不能说明什么**：8 条样本、2 章、单本书，不足以判断"证据不足"的长期占比，
更不足以断定复检准确率。要下结论得跑整本（预算也要按整本给）。

## 这轮实测抓到两个 bug（都是"看起来有保护、其实没有"）

### 1. 锚点校验插错了函数（已修）

第一次跑出来 `伏笔锚点校验异常，已跳过: name 'chapter_content' is not defined`，
`anchor_stats` 全是 0 —— 但**账本里 8 条都有锚点**。

原因：校验代码被我插进了 `_parse_response()`，那个函数里根本没有正文变量；
异常被 `except` 吞成一行 warning，于是"每章都校验"实际是"每章都没校验"，
锚点全是模型自己说的，一条都没核对过。

修法：把校验块移进 `analyze_chapter()`（那里才有 `chapter_content`）。
守卫用例 `test_anchor_quote.py::test_verification_runs_inside_analyze_chapter`
用**源码位置 + 形参名**把这条钉死——不检查行为，直接检查"它是不是在拿得到正文的地方被调用"。

### 2. 脚本缺代理净化（已修）

`httpx.InvalidURL: Invalid port: ':1]'` —— 本机 `NO_PROXY` 里的 `[::1]` 被当 URL 解析。
测试里由 `pytest_isolation.sanitize_proxy_env()` 处理，**独立脚本必须自己做**，已加。
