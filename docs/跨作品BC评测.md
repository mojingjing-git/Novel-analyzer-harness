# 跨作品 B/C 评测协议 v1

目的：检查通用机制能否迁移。开发回归、跨作品检查、最终保留集分别报告；机器生成参考标签不得称为人工金标准。

## 抽样与隔离

`scripts/experiments/bc/bc_corpus.py freeze` 只输出书目、文件指纹、抽样坐标，不输出小说正文。计划必须先写到 JSON：

- `schema: bc_corpus_v1`，固定 `seed`、`windows_per_work`、`window_chars`。
- `works` 每项提供 `work_id/title/path/split`，split 为 development/validation/holdout。
- `previously_exposed_titles` 声明已用作品；`group_id` 归并不同书名的同作/修订版，`prior_exposure` 声明已读状态。
- `protocol_files` 冻结抽样实现和本协议的指纹。不得包含运行配置或密钥。

同一作品按整本隔离，不允许章节随机拆成开发和验证集。相同书名、显式别名组、忽略空白/字宽后相同正文均阻止重复入组。算法不能自动识别所有改名或大幅修订版本，需维护 group_id；也不能知道模型预训练是否见过该书。

正文严格解码，字符坐标保留原始换行。在等长的前/中/后三段各用种子哈希确定起点；最多移动400字符以贴近换行，不按情节挑选。短文不满足计划时直接报错，不自动补选容易样本。窗口不等于整章/完整故事，边界状态与缺上下文必须保留。

冻结目录不覆盖旧目录；导出时核对完整来源与窗口指纹。`export` 在输出正文前写曝光记录，失败也保守记录。`status` 显示哪些书已导出。直接在工具之外阅读正文、跨目录重建清单的曝光仍须主动登记；此机制用于防误操作，不是防篡改系统。

```powershell
python scripts/experiments/bc/bc_corpus.py freeze --plan <计划.json> --bundle <全新冻结目录>
python scripts/experiments/bc/bc_corpus.py export --bundle <冻结目录> --work book_a book_b --purpose validation --output <盲读包.json>
python scripts/experiments/bc/bc_corpus.py status --bundle <冻结目录>
```

holdout 不可作为 validation 导出。最终导出要求 `--purpose final_evaluation --run-spec <运行声明.json>`，声明至少包含 run_id、model、prompt_sha256、max_calls、max_output_tokens、reference_policy；抽样协议指纹必须仍一致。导出动作只冻结声明，不替代执行器对实际模型/提示词/预算的检查。保留集曾导出、用于开发后不能再作为未曝光最终集。

## B：先读原文，再对照产物

盲读包只含原文，不含分析器候选、回答或模型判定。标注者先记录可定位的问题/伏笔、事实、局部回答、语气限制、依赖外文的疑点。每条标注需要原文引文与范围、标注者、标注时间、样本指纹。

冻结标注后才对照原生产链路，分别记录：未登记、已登记但取材漏掉、取到但判断错、已判断但落账/呈现遗漏。争议、需要前后文和纯猜测单独统计。抽样窗口的局部覆盖不能报告成全书伏笔召回率；只审查已有候选更不能测出“从未登记”的漏项。当前工具只生成盲读包，不自动生成完整 B 真值或召回率。

## C：候选审计与分项契约

真实候选审计需固定原问题、原关闭条件、原候选答案与原文。同一输入用不同方法评测，禁止看到结果后改答案/标签。

`acceptance_gate.py --claim-audit` 试验性启用 `claims_v1`：模型输出按顺序覆盖完整答案的 units，每项声明关系、事件/转述/假设/梦境/计划范围、说话者、指代一致性、独立逐字引文。程序检查完整覆盖、引文唯一定位、范围和说话者声明一致。失败保留存疑，部分回答仍不能关闭整条。

这不证明模型拆分足够细或其语义分类正确；模型把梦境误分为现实仍可能通过。`eligible` 只表示声明自洽且可定位。该模式默认关闭，以保留旧接口；开启会改变样本指纹，标签需重新绑定。试验期间不修改生产账本。

## 首批预登记（2026-11-05）

- 按文件名选工业、游戏、日常、历史四个预设题材组，每组一部验证作品、一部保留作品。题材标签仅用于多样性安排，不是外部权威分类，也不代表全部405个文件的随机样本。
- 验证：大国重工、全职高手、回到过去变成猫、唐砖。保留：超级能源强国、王者时刻、我家老婆来自一千年前、绍宋。
- 已使用的道诡异仙、大奉打更人、三侠五义明确排除。每书3个4000字符窗口，共24个窗口；种子 `bc-cross-work-20261105-v1`。
- 首轮只做 C 契约可运行性检查：按预定规则取每部验证作品的第一个窗口，各构造一条有依据答案与一条范围/事实扩写答案，共8条、两种方法共16次逻辑调用。构造标签来自 Luna 盲读提案、主代理核验，属于模型辅助参考，不是独立人工金标准或自然错误率。
- 参考题目先冻结再调用当前复检模型；两个方法使用同一候选与同一原文。记录原始响应、代码/提示词/样本指纹、token、延迟、调用失败。语义正确性、协议有效率、成本分开报告；不按结果补选题目。
- 原文和盲读包保存在被忽略的 `workspace/bc-evaluation/` 中，书目计划、协议和无正文汇总保存在 docs；不改原小说。
- 其余验证窗口用于后续原文先行的 B 标注。四部保留作品本轮不导出、不交给模型。
