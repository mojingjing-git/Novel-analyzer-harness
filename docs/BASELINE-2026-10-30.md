### 3.1 环境噪声已根治（S0-4）

历史现象：本机 `NO_PROXY=localhost,127.0.0.1,::1,[::1]`，其中**方括号写法 `[::1]`** 被 httpx 当 URL 解析，端口段 `:1]` 转 int 失败：

```
ValueError: invalid literal for int() with base 10: ':1]'
  → httpx.InvalidURL: Invalid port: ':1]'
  → backend/core/llm_client.py:143  self.client = AsyncOpenAI(...)
```

由此产生 **74 个假失败**（`test_anthropic_provider.py` 7 例、`test_summary_checkpoint.py` 6 例等，凡构造 `AsyncOpenAI`/`AsyncAnthropic` 的用例全挂）。

S0 处理：`pytest_isolation.install()` 在任何 `backend.*` import 之前调用 `sanitize_proxy_env()`，把 no_proxy 里的方括号 IPv6 改写成等价裸写法（`[::1]` → `::1`），并丢弃端口段不可解析的代理 URL。**只改本进程 `os.environ`，不触碰宿主全局环境**（PLAN §1.3）。

验收：在**原始未清理**的代理环境下直接 `python -m pytest`，892 个用例全绿（此前同环境为 74 failed / 790 passed）。

## 4. 配置字段基线（仅字段名，不含任何密钥值）

`config.example.json` 顶层键：`analysis` / `api` / `gui` / `knowledge_file` / `working_directory` / `workspace_dir`

`analysis` 下 37 个键。

> 基线用途：S2 引入新数据契约后，本清单用于核对"没有因为契约改造而丢字段"，也用于回归"GUI 保存后字段不丢失"。
> 已知遗留缺陷（C-21，非 S0 范围）：`backend/core/analyzer.py:61-69` 只把 7 个参数传进 `PromptBuilder`，因此 **Prompt 侧**的 `max_relationships`(默认 15) / `max_verified_facts`(15) / `max_themes`(8) / `max_content_chars`(30000) **始终取 `prompt_builder.py:100-103` 的默认值，未接线到配置**。
>
> 三点需要澄清，避免误读：
>
> 1. `max_verified_facts` **在 config 中确实存在**（`settings.py:188`；`config.example.json:76`、`config.json:119` 均有值），并非"不在 config 中"。但它驱动的是 **KB 裁剪**，与 Prompt 注入上限是两个独立口径（KB=200 / Prompt=15）。
> 2. **KB 裁剪本身有三条路径且取值不一致**：`memory_state.py:414` 读配置（经 `pipeline.py:327` 注入的 `kb_limits`）；`knowledge_base.py:309` 与 `knowledge_base.py:476` 硬编码 `MAX_VERIFIED_FACTS`。因此改配置只影响第一条，另外两条不跟随。
> 3. 另外 3 项（`max_relationships` / `max_themes` / `max_content_chars`）确实不在 `AnalysisConfig`（`settings.py:143-152` 无此三键）。
