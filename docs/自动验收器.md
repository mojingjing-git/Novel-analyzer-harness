# 自动验收器（打捞结果预筛）

`scripts/acceptance_gate.py` 对打捞管线产出的"已验证"候选做二次预筛，把人工复核量从
"逐条翻查"压到"只看机器没把握的"。它不写账本，只输出三值判定与理由。

## 判定结构

| 层 | 规则 | 结果 |
|---|---|---|
| 机械-硬 | 支持引文与登记锚点原文互为子串（复述已知）；答案 2-gram 覆盖率 ≥0.85（无信息增量） | 拒绝 |
| 机械-软 | 证据章 ≤ 锚点章（同段内容不构成后文回收）；判定标准要求排他而答案无排除性表述 | 存疑 |
| 语义（NLI 单次调用） | restating（复述）/ off_topic（答非所问） | 拒绝 |
| 语义 | answer_ok 且无软疑点 | 接受 |
| 语义 | unclear / 调用失败 | 存疑 |

判定标准先按 `criteria_logic` 分型（出现"或/任一/之一"为 OR，出现"以及/和/与/并"为 AND），
NLI 按类型判定闭包：OR 型满足任一完整分支即可，AND 型须全部满足。不分型会让 OR 型标准的
合法部分覆盖被误判为不完整回答。

## 用法

```
python -u scripts/acceptance_gate.py --exam <考卷.json> --output-dir <输出目录> \
  --model <通道> --concurrency 3 --stamp <标记>
```

考卷每条需要：`fs_id / question / criteria / description / anchor_quote / anchor_chapter /
answer / quote / chapter`，可选 `label`（支持/不支持/待裁决）用于评测。

评测输出混淆矩阵：误报拦截率、支持保留率、危险错误（不支持被判接受）、待裁决项分布。

## 当前操作点（55 条已标注考卷）

- 误报拦截 10/12（7 拒绝 + 3 存疑），支持保留 29/31，危险通过 2（fs_655 混合语义、fs_1073 跨事件归并）；
- 人工量 55 → 约 14（存疑 10 + 接受项抽检 10%）；
- 遗留 2 条属语义级，机械规则与单模型 NLI 都拦不住，需双模型交叉或人工。

结论：**验收器作预筛，不作唯一裁量依据**；落账仍需人工确认存疑项并抽检接受项。
