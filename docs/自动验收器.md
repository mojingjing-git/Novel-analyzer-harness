# 自动验收器（打捞结果预筛）

`scripts/acceptance_gate.py` 读取打捞候选，分别核对关闭条件是否满足、候选答案是否忠于原文，输出接受/拒绝/存疑。它不写生产账本。模型通过不代表人工真值。

## 输入与关闭条件

`run_salvage.py` 会输出 `acceptance_input_<运行戳>.json`，自动携带问题、原关闭条件、共享预登记、逐分支引文和同一次取证的原文段。

- 预登记由 `backend/common/closure.py` 校验；打捞与验收共用条件归约，验收不按“或/以及”等关键词重新分类。
- 预登记含 `criteria_source` 时必须与当前条件一致；变更或无法表达的条件保留存疑。
- 每个命中分支必须有合法 `evidence_id` 和至少6字的逐字唯一引文。程序核验位置后才能参与 AND/OR 归约；语义是否成立仍由模型与独立复核判断。
- 旧考卷未提供预登记时使用 UNKNOWN，由模型按完整语义判断，不猜测顶层关系。

## 验收判定

|检查|处理|
|---|---|
|支持引文完全落在旧锚点内|拒绝：本条引文本身没有新增信息|
|长引文包含旧锚点、答案高文本重合|复述风险信号；明确有新增命题时允许解除，不能仅凭相似度硬拒绝|
|证据不晚于锚点、排他条件缺少排除性表述|保留存疑|
|NLI为restating/off_topic|拒绝|
|NLI无法判断、调用失败、上下文缺失、引文未定位|存疑|
|模型明确确认criteria_satisfied与answer_supported，分支证据有效且无未解决疑点|接受|

NLI输入包含原文上下文，要求区分事实、梦境、比喻、人物推测和转述，核对同一人物/物件/事件/时段。“条件已回答”与“答案中每个断言都有根据”分别记录，防止部分关闭时顺带扩写。

## 使用

新打捞结果直接送入验收：

```powershell
python scripts/acceptance_gate.py --exam <acceptance_input_运行戳.json> --output-dir <独立评测目录> --model <通道>
```

旧考卷先补齐原文并冻结（不加载模型配置、不调用模型）：

```powershell
python scripts/acceptance_gate.py --exam <旧考卷.json> --blocks <blocks目录> --prepare-only --output-dir <独立评测目录>
```

`--blocks` 中 chapter 必须是原文块文件序号，不能混用番外的文内章号。引文必须在指定文件唯一匹配；全文超过24000字符时报告上下文超限，不静默截掉后续限定语。随后使用生成的 `acceptance_prepared_*.json` 进行评测，不必再次传 `--blocks`。

## 标签与评测

每项都有 `sample_id`：绑定问题、条件、候选答案、具体引文、原文章号、预登记与证据文本。独立复核者确认标签对应这一完整输入之后，才可把 `label_sample_id` 设为该 `sample_id`。仅冻结输入不会自动认证历史标签。

- 标签可为支持/不支持/待裁决，也可以没有标签。
- 无绑定、版本已变更、未标注的项仍可进行判定，但不计入准确性相关分母。
- 动态统计支持保留率、硬拒绝率、阻止自动通过率、危险通过数及标签状态分布。
- 没有相应标签时指标为 `null`（N/A），不能解释为0%或100%。
- 标签绑定只保证对应输入版本一致，不证明标签本身正确。开发回归集与未调参验证集应分开。

旧考卷或旧模型输出不符合新协议时，应保留原文件，生成新版本再评估；不能把旧通过数与新规则通过数混合计算提升。

## 部分回答与答案扩写

输出另有 `assessment_status`：`partial_answer` 表示模型认为部分事实有依据但条件尚未整体满足；`answer_overstated` 表示条件可能已回答，但候选答案含无依据扩写；`accepted` 与 `unconfirmed` 表示接受与未确认。这些分项判断不自动更新账本，也不等同人工证实。

验收器默认使用已配置的复检模型、地址、密钥和推理档位；显式 `--model` / `--base-url` 仍可覆盖。

可选 `--claim-audit` 启用逐断言证据契约，要求完整答案分项覆盖、每项引文和范围声明一致。该模式仍是试验性预筛，不是语义证明；协议、隔离规则及跨作品用法见 [跨作品BC评测](跨作品BC评测.md)。

`--claim-contract claims_v2` 选择第二版：程序固定答案片段编号；模型分别声明说话者、世界、语气与实现进度。编号覆盖、引文定位与各维度比较由程序检查，模型仍可能判断错。该开关优先于 `--claim-audit`，默认仍不启用。第一轮失败原因及第二版开发复检计划见 `docs/research/bc-cross-work-2026-11-05/`。
