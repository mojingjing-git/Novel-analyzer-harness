## 1. 阶段 0-2 遗留的真问题（抽查发现）

阶段 0-2 的定位规则是「单元内优先 → 全书纯字面取**最早**出现」。
理由是"伏笔埋在前面，全书首次出现就是埋设处"。**抽查 12 条多文件引文，这个规则错了 6 条**：

| 引文 | 采集侧章号 | "最早"落在 | 正确？ |
|---|---|---|---|
| 血屠三千里，血屠三千里，请朝廷派兵讨伐…… | 96 | 324（第 94 回） | ✗ |
| 金刚神功？！ | 124 | 364（第 134 回） | ✗ |
| “福如……东海，大吉……大利。” | 171 | 85（第 85 回） | ✗ |
| 但行好事，莫问前程。 | 106 | 261（第 31 回） | ✗ |

错的都是**伏笔金句**——恰恰是最该被好好核对的那一批。取错文件 → 取错证据窗口 → 判定跟着错。

离线对比（1669 条候选，全库纯字面定位）：

- 「最早出现」命中采集侧章号的文件：**365** 条；
- 「回号优先」命中采集侧**回号**的文件：**1669 条里 1665 条两法一致，4 条不同**，
  而这 4 条回号优先**全部正确**（与采集侧回号一致）。

## 2. 决策：身份仍是文件，但**定位顺序**要按可信度分级

采集侧记的章号不是身份（阶段 0-2 的结论不变），但它是**模型在真实上下文里给出的位置提示**，
比"全书最早出现"可靠得多——上面 4 条就是证据。

三段式定位：

1. **回号优先**：用文件内解析出的回号建 `回号 → 文件列表` 索引；
   采集侧章号 → 候选文件 → 逐个找引文 → 命中即用；
2. **全书兜底**：上一步没命中 → 全书纯字面取最早出现；
3. **记置信度**：命中的文件与采集侧回号相差超过阈值 → 标 `low_confidence`（AGY P3）。

**同回号多文件**（实测第 96 回对应 5 个文件）：按文件序号升序逐个找，第一个命中者为准。

| 7 | `backend/tests/test_text_units_identity.py` | 补：回号优先正确性、同回号多文件、低置信度标记、1.x 行为不变 |

## 4. 验收（可脚本判定）

| 项 | 标准 |
|---|---|
| 四分母断言 | 回号优先命中 + 全书兜底命中 + 确凿不存在 = 1669；**存在但定位失败 = 0** |
| 回号优先正确性 | 抽样人工核 ≥ 10 条（含上表 4 条关键伏笔） |
| 兜底率 | 全书兜底命中 ≤ 5%（其余靠回号索引直接命中） |
| 低置信度标记 | 阈值内命中不标、超阈值必标；标记数与人工抽查一致 |
| 1.x 不变 | `unit_noun="章"` 时行为与阶段 0-2 完全一致 |
| 全量门禁 | `scripts/run_tests.py` 全绿 |

## 5. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 回号索引依赖标题解析；无标题的文件进不了索引 | 索引缺失 → 自动落到"全书最早"兜底（不是错误路径） |
| 同回号多文件时取第一个命中的，可能是另一处重复引用 | 记 `locate_mode` 与候选文件列表，人工可查；低置信度机制兜住跨度过大的情况 |
| 低置信度标记让判定看起来"更差" | 只是**标记**，不改判定、不改状态；报告里单列一栏供人工复核 |
| 回滚 | 改动集中在 `text_units.py` 与 `recheck_v2.py` 的定位段；`git revert` 即可 |

## 6. 不做什么

- 不改采集侧、不改账本 schema、不改结果模型。
- 不引入自动降级门禁（弱模型盲复核精确率 ~80%，不能当门禁）。
- 不改 `EvidenceIndex` 的取窗半径与检索语义。
- 不重跑整本（阶段 0 收口时统一跑）。
