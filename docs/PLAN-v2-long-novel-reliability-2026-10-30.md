## 1. 产品边界与执行规则

### 1.1 新版本从独立数据空间开始

1. 新数据格式族固定为 `novel-analyzer-vnext`，初始 `schema_version = 1`。格式族与版本共同识别文件，不沿用旧账本 v3/v4 的解释规则。
2. 使用独立默认工作区 `workspace_vnext/`、独立队列 `queue_state_vnext.json` 和书目索引；运行配置使用独立的新版本配置文件，首次启动创建默认配置并由用户填写凭据。不得根据旧配置中的路径自动扫描旧分析目录。
3. 原始 TXT/DOCX 可以作为新导入源；旧 `chapter_*_result.json`、`knowledge.json`、`rolling_summary.json`、伏笔账本、聚合文件及总结 checkpoint 一律不复用。
4. 缺少格式标记或版本不支持时，返回明确的 `UNSUPPORTED_ARTIFACT_FORMAT`。界面提示“此目录不属于本版本，请从原文创建新项目”；不能猜测字段、回退解析或自动转换。
5. 旧目录不属于新数据空间。实现不需要打开、覆盖、删除或归档旧产物；新格式拒绝测试只使用临时合成文件。
6. 所有新版本读链必须经过格式校验和有效产物索引，包括队列恢复、书目发现、API、图谱、地图、角色卡、聚合、导出、风格与总结服务。只修改 `from_dict()` 不算完成。
7. 不保留旧字段投影或双写桥接：事实直接使用 `fact_records`；人物共现和语义关系直接分开；伏笔直接使用新状态。API、DTO 与页面同批调整。

### 1.2 必须保留的运行能力

保留长篇分块分析、并发、暂停/取消、审核跳过、可控重试、断点恢复、自动总结、真实费用统计和现有厂商接入能力。这些能力需要在新契约下重新验证。

- `FAILED`、`SKIPPED`、`CANCELLED`、账户错误导致的 `BLOCKED` 必须区分。审核跳过不能被算作分析成功；取消不能被算成模型失败。
- LLM 提供提取结果、候选假设和原文核对枚举；程序校验来源、顺序、身份、状态与提交条件。模型自评置信度不能授权升级，`AUTO_RESOLVED` 仅表示有原文依据的自动判定，不保证零误回收。
- 原文语义核对并入已有 recheck 阶段；默认不新增阶段外语义复核或 rolling 重建调用。候选增多及原文输入可能增加请求、Token 或重试率，必须测量并受预算约束，不能承诺零额外调用或 Token。
- 保留原始提取与来源记录；对 Prompt 和界面限制窗口，不以 LRU 删除全书权威数据。
- 本期不引入多 Agent、向量数据库、全量数据库改造或自动写小说模块。

### 1.3 分批工作方式

- 每批先读实际函数、消费者和测试，先补能失败的回归，再修改实现。源码前提不符时修订该批设计，记录证据。
- 一次处理一个主批次，每批形成单独提交或可审查 patch；若未获提交授权，仅交付 patch。优先完成一个数据域，避免同时重写 pipeline、memory_state、final_summary 的主体。
- schema 变更同批更新写入、读取、恢复、API、DTO 与直接页面消费者。每个阶段均须可验证，不把全部前端适配留到最后。
- 整体执行授权允许按依赖串行推进；只授权单批时完成该批后停止。付费实验、预算扩展和真实用户数据操作遵循届时的授权范围。
- 默认测试使用写前隔离的临时目录与 mock LLM；不连接在线模型、不读取真实密钥。不得全局修改代理环境。
- 业务代码修改后更新 `agent.md` 的相应当前架构说明和 CHANGELOG；设计记录与审查证据放在 docs，避免继续追加长篇历史流水账。

## 2. 在实现前固定的新数据契约

本节在 S2 交付模型、验证器和契约文档，后续阶段按数据域接入。可以扩充必要字段，但不能更换这些语义而不更新依赖和测试。

### 2.1 来源、分块与结果

| 对象 | 必需字段与规则 |
| --- | --- |
| 项目 manifest | `format_id`、`schema_version`、稳定 `book_id`、`workspace_id`、章节顺序、当前源快照、有效分块/结果引用、`revision` |
| 章节源 | 稳定 `chapter_id`、故事顺序、展示章号、规范文本 `content_hash`、原始导入来源；章号不要求连续 |
| 原文引用 `source_ref` | `book_id`、`chapter_id`、`content_hash`、`start`、`end`、`quote`；偏移为规范文本 Unicode 码点，左闭右开 |
| 分块身份 | `block_signature` 绑定实际有序 `source_chapter_ids`、各章 hash 和切章/分块策略版本；块起始章仅供展示 |
| 分析结果 | `result_id`、块身份、实际来源章节与 hash、提取数据、模型/Prompt/策略标识、上下文依赖及其指纹、结果状态 |
| 派生产物 | 格式标记、产物 ID、依赖引用与指纹、生成策略、覆盖范围、完整性状态；时间戳不参与内容指纹 |

具体要求：

1. 先把导入小说保存为可追溯的规范章节文本；换行等规范化规则固定版本。引用定位只能指向保存的同一份规范文本，不能对照摘要定位。
2. `chapter_id` 不由列表下标或当前最大章号生成。重新排列或在前面插章不能让已有 ID 自动指向其他内容；无法匹配的来源建立新身份。
3. 续跑同时验证块组成、正文 hash、实际 Prompt 输入、模型关键配置与策略版本。相同起始章、相同 `block_size` 不代表相同任务。
4. 结果读取基于当前 manifest 的有效引用，不用目录中所有 JSON 的 glob 结果作为事实全集。同一章节的多个重算版本不能同时合并；活动分块必须无重叠。
5. 改变分析起点、块大小或章节集合时生成新的分块方案；只复用块组成和输入依赖完全一致的结果。重叠块不能通过截取其章号标签冒充单章知识。
6. 每个分析/总结运行固定一个输入快照。在请求执行期间源文本或活动结果变化，旧任务仍记录消耗，但提交时标为过期，不能覆盖新快照的活动引用。
7. 修改早期来源或替换结果，沿实际依赖将后续产物标为 `STALE_INPUT`，包括使用了该结果作为上下文的分析结果。保留原版本供审计；不静默将旧上下文下的结果显示为最新，也不自动启动大规模重算。
8. 缓存键包含实际使用的依赖；全书 manifest 的变化可触发依赖检查，但不能让追加后卷内容无条件失效前卷缓存。整书随机 ID/全书统计也不能混入前卷 Prompt。
9. 格式标记、来源 hash、权威实体身份与依赖由程序绑定，不能由模型输出覆盖。必需字段或含义发生不兼容变更时提升对应 schema/策略版本；本版本开发中的旧测试产物也明确拒绝或重新生成，不增加降级解析。

建议在现有 models 和文件读写模块旁增加小型来源模型与产物验证器；不先建设通用存储框架。

### 2.2 知识库和关系

- `fact_records`：`fact_id`、陈述、提取来源、可选原文引用、`verification_state`、冲突引用。初始为 `UNVERIFIED`；原文匹配成功可为 `EVIDENCE_LOCATED`，这不等于语义已核实。
- 人物状态：人物标识、状态文本、来源顺序键、来源结果版本；运行期与磁盘重建使用相同归约规则。
- `cooccurrence_edges`：人物对、确实共享的章节/来源、次数。只有块级来源时不能标成“同章共现”；可单独展示“同块出现”，或不生成该边。
- `semantic_relationships`：关系类型、方向、来源和证据、提取/核验状态。没有明确关系记录时保持为空，不用同章两两配对填充。
- 历史事实与人物存档保留完整；Prompt 限额和热缓存限额单独命名。不得继续把模型事件摘要命名或展示为“已核实事实”。

### 2.3 伏笔身份、候选与全自动状态

| 对象 | 约定 |
| --- | --- |
| 原始出现记录 | `occurrence_id` 持久化，绑定提取结果版本、原始局部记录及来源；含描述、类型、重要度、置信度、可定位引用或缺证据标记 |
| 伏笔实体 | 稳定 `entity_id`、成员 occurrence、原悬念及其版本、`entity_revision`；同一物件的不同悬念不能仅凭词面相似合并；`fs_001` 仅为展示编号 |
| 候选回收 | 持久 `candidate_id`、实体/悬念版本、`proposed_answer`、埋设/回收来源引用、`evidence_id`、上下文、`adjudication`、`reason_code`、任务/策略指纹及裁决历史 |
| 证据身份 | 来源锚点哈希，绑定 `book_id + chapter_id + content_hash + start + end`；展示序号 `display_index` 与身份分离 |
| 解决维度 | `resolution_state = OPEN / PROPOSED_RESOLVED / AUTO_RESOLVED`，由全部当前有效候选归约，单个模型响应不直接写实体状态 |
| 最近提及维度 | `recency_state = RECENT / STALE`，按原始出现记录和展示截止点计算，与是否解决相互独立 |
| 裁决审计 | 独立 decision 记录，含目标候选、来源版本、输入/输出裁决、原因、实体 revision、时间和 `decision_actor = evidence_verifier`；被取代结论保留 `superseded_by/superseded_at` |

约束：

- ID 不由全书排序、截断名次或分组遍历序号决定。补入早期线索不能挪用已有实体 ID。
- 重复总结复用已保存的出现记录和实体登记；重新提取产生新记录版本，不按数组下标继承其他实体或版本的结论。`entity_id` 首次分配后不挪用；描述指纹只用于检索、变更和缓存，不充当实体身份。
- 保留所有原始出现记录。重要度/分类筛选与目录上限只影响视图及调用预算，不物理删除低排名数据。
- 跨记录去重使用稳定顺序、固定规则和持久化成员映射；新增未来记录不能改写早期记录已分配的实体 ID。
- 对涉及多个既有实体的合并/拆分保留独立建议，不影响正常运行，也不要求用户处理。应用受支持的映射策略时产生新版本并使依赖失效，不能继承另一实体的自动回收状态；首版不自动执行重写全书身份的二次聚类。
- 同一实体的未解决复述应新增 occurrence、更新最近提及，不升级解决状态；当前证据与最后出现位置随有效来源同步更新，不能只追加“不存在的 ID”。
- 无效候选只影响自身。来源变化或新反证推翻现有支撑时，仅使相关候选裁决失效，再以其余有效候选重算；历史保留，不把已失效的 SUPPORTED 永久冻结为权威结论。
- `STALE` 只表示近期未检测到。它不代表已解决、作者遗忘、无价值或无需复检；禁止按 active 数量硬凑比例。
- recheck 使用接口 B：看到明确标为“未经核实的待核对假设”的候选答案，返回 `SUPPORTED / DIFFERENT_ANSWER / CONTRADICTED / INSUFFICIENT`。不传递第一阶段的通过结论、自评置信度、解释或推测事件时间作为核实信息；原文中的真实时间和定位范围必须保留。
- 程序不比较两段自由文本的语义。`SUPPORTED` 仍是模型判断，程序仅在来源、引用、顺序、输入范围及枚举校验全部通过后形成候选级裁决；不声称两阶段统计独立，也不把模型声称已搜索等同于穷尽原文的证明。
- 词面分数只用于检索/排序、异常提示和去重线索，不参与自动通过条件。这些反例不支持“负相关”或“回收必然降低重合度”的推论。
- 运行流程没有确认、驳回、撤销、人工覆盖接口和操作队列。页面只读展示引用、核对范围和裁决原因；统一措辞为“自动判定已回收 · 查看原文依据”，不使用暗示已证明无误的回收标签。

候选级与实体级状态固定如下：

| 维度 | 规则 |
| --- | --- |
| 候选裁决 | `PENDING / SUPPORTED / INSUFFICIENT / CONFLICT / INVALID`，与调用任务状态分离 |
| 枚举映射 | 程序可确定的来源/实体 ID/版本/引用/顺序错误 → INVALID；输入过期另记 STALE_SOURCE；模型 DIFFERENT_ANSWER 或 CONTRADICTED → CONFLICT；模型 INSUFFICIENT、缺少反证核对记录或材料被硬截断 → INSUFFICIENT |
| SUPPORTED 准入 | 原文引用及程序生成的支持段定位正确、来源与顺序有效、输入完整性通过、recheck 返回 SUPPORTED、反证核对已执行且未给出反证或材料不足原因 |
| AUTO_RESOLVED | 全部当前有效候选中存在适用于当前来源/策略的 SUPPORTED；已被反证推翻、被取代或过期的裁决不参与 |
| PROPOSED_RESOLVED | 没有有效 SUPPORTED，但存在有效 PENDING、INSUFFICIENT 或 CONFLICT；这是候选存在的状态，不要求用户处理 |
| OPEN | 当前没有有效候选；不等于程序证明原文从未回收 |

实体归约读取同一 revision 下的候选集，不以到达顺序覆盖。新出现一个 INVALID 不抹掉另一候选的有效支持；反证明确推翻原支撑时先更新对应候选，再归约。相同语义输入命中缓存时复用原 candidate_id；新输入可产生新候选/裁决版本并关联历史，不能每次重放新建 UUID。

**复检覆盖披露（D-13）**

全书复检必须持久化以下字段，供 T43 / T44 / T46 核对：

| 字段 | 内容 |
| --- | --- |
| `recheck_status` | `NOT_RUN` / `RUNNING` / `COMPLETED` / `PARTIAL` / `STOPPED`。与 `resolution_state` **正交**，不得互相代替 |
| `recheck_task` | `task_key`、`strategy_version`、`source_revision`、`started_at`、`finished_at` |
| `recheck_coverage` | 见下 |

`recheck_coverage` 分两类计数，**不得混为一谈**：

- **最终分类**（互斥，其和等于候选总数）：`SUPPORTED` / `INSUFFICIENT` / `CONFLICT` / `INVALID` / `STALE` / `NOT_CHECKED`
- **过程计数**（可重叠）：`submitted`、`evidence_located`、`llm_calls`、`cost`

`INVALID` 按 `reason_code` 细分：`QUOTE_NOT_FOUND` / `QUOTE_AMBIGUOUS` / `WRONG_ENTITY` / `ORDER_VIOLATION`。
`NOT_CHECKED` 按原因细分：`BUDGET_SKIPPED` / `MATERIAL_TOO_LARGE` / `FAILED` / `CANCELLED` / `NOT_RUN`。

**归类约束**：缺少反证核对记录属**材料不足**，归 `INSUFFICIENT`，**不得**归入 `INVALID`（与上面的枚举映射一致）。

**状态判定（按顺序，互斥）**：

1. 未进入复检流程 → `NOT_RUN`
2. 正在执行 → `RUNNING`
3. 已结束且**被取消** → `STOPPED`
4. 已结束，`NOT_CHECKED` 计数 > 0（无论是否另有 `SUPPORTED`）→ `PARTIAL`
5. 已结束、无 `NOT_CHECKED`，且汇总已提交 → `COMPLETED`

`NOT_CHECKED` 已属最终分类，因此**不能**与"全部候选都有最终分类"并存被判为 `COMPLETED`。**不得**仅因汇总对象存在就宣布完成；覆盖汇总缺失时不得标记完成。候选集为空时，只有**实际完整执行过一次复检流程**才记 `COMPLETED` 且计数为 0；未执行仍记 `NOT_RUN`。

### 2.4 缓存与任务完成状态

任务完成与伏笔是否解决是独立状态。卷摘要、reconciliation 和全书 recheck 均持久化：

`task_key`、阶段、实际依赖指纹、相关实体/出现记录版本、Prompt/策略版本、模型关键参数、所属运行/预算组、状态、结果引用、实际尝试/Token、失败原因。恢复保留原 `run_id` 与已用预算；缓存键不包含会使跨运行复用失效的随机 run_id。

任务状态至少区分 `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`BUDGET_SKIPPED`、`STALE_INPUT`。合法执行但未找到支持也是 SUCCEEDED，不能把候选的 INSUFFICIENT/CONFLICT 当成网络失败。进程退出后遗留的 RUNNING 不能伪装成成功。

| 结果 | 是否写成功完成标记 | 恢复规则 |
| --- | --- | --- |
| SUPPORTED / INSUFFICIENT / CONFLICT | 是 | 任务键、实际来源/上下文、悬念/候选、模型及策略指纹不变即复用；同输入不再循环询问 |
| 本地校验得到 INVALID | 是，记录未调用模型及原因 | 复用同一有效输入的校验结果；来源/定位策略/悬念变化则失效 |
| STALE_SOURCE / STALE_INPUT | 不作为当前输入的成功结果 | 保留旧版本记录并退出本轮，输入快照稳定后生成新任务；不反复处理旧引用 |
| BUDGET_SKIPPED | 否 | 提高预算或补足本次额度后，同一 task_key 可继续；不能缓存为语义否决 |
| FAILED / CANCELLED / PENDING | 否 | 下次恢复按有界策略处理，不在后台无限重试 |

- 同输入复用成功结果；失败只补失败项，未执行项由下一次预算决定。增大预算不使已成功任务失效，也不能被成功缓存阻止。
- 缓存失效基于依赖，不能把整个 checkpoint 目录一删了之。
- 最终报告依赖当前有效候选裁决及实体归约版本，变化时准确失效；不依赖这些状态的原始提取和卷摘要不必重算。
- 原始候选不因消费而删除。状态归约以稳定候选键去重，重放、恢复不能重复追加审计；新结果以 superseded_by 关联被取代结论，不能静默覆盖。
- 费用按实际 API 尝试统计，缓存命中独立计数，不重复累计费用，不把已付费但后来过期的结果从账单抹掉。

### 2.5 错误判定（ErrorVerdict）与调用结果

- 新增最底层叶子模块 `backend/core/error_types.py`：共享枚举（`ErrorClass` / `Confidence` / `SourceChannel` / `ErrorScope` / `UsageStatus`）与纯数据类型（`ErrorVerdict` / `LLMResult`）。`error_taxonomy` 与 `llm_stream` 单向依赖它，**不得反向**（否则策略层依赖协议层）。
- `ClassVerdict` 保留为**分类器内部输出**，字段不变（既有 37 条 taxonomy 测试不动）；由 `to_error_verdict(...)` 提升为 `ErrorVerdict`。
- `ErrorVerdict` 字段：`cls / confidence / source_channel / provider_code / http_status / action / scope / retry_after / message`。`action` 由**唯一的策略函数**计算，除 `cls × scope × policy` 外还必须接收**重试上下文**（连续审核命中次数、剩余预算与剩余轮数），因此不能只由错误类别推导；外层只消费计算结果，不再自行推导。`message` 只用于展示与日志，**任何判定不得读取它**。
- `LLMResult` 字段：`success / content / error / tokens / usage_status / call_stats / verdict / attempts`。`tokens` 为 `Optional[Tuple[int,int]]`：未拿到 usage 时为 `None` 且 `usage_status=UNKNOWN`——**不得**写成 `(0,0)`，**不得**沿用前次 attempt 的计数。
- `StreamChunk` 与 `StreamResult` 均追加 `verdict: Optional[ErrorVerdict]`。**流式块必须携带完整契约**（含 `scope` 与 `retry_after`），不允许只在终结结果上补齐，避免中途信息丢失与多处字段互相矛盾。
- `scope` 取枚举值 **`ACCOUNT_GLOBAL` / `REQUEST_LOCAL` / `TRANSIENT` / `UNKNOWN`**（与 §4 S1、S8a 及 T03/T25 使用同一套词汇，不得另立 `CALL`/`BLOCK`/`ACCOUNT`）。**不默认成 `REQUEST_LOCAL`**，不允许自由字符串。`ACCOUNT_GLOBAL` 绑定实际端点与**不含密钥的凭据指纹**；`UNKNOWN` 必须保留，且作用域不明时**不得**凭字符串升级为账户熔断。
- `chat` / `chat_with_retry` / `chat_auto` 统一返回 `LLMResult`，**不提供位置式解包**，旧元组形状在 S1 一次性删除，不留兜底。
- 判定沿革：同一错误逐层包装保留**原始原因**；不同 attempt 各自留记录，终态取**导致停止的那次**判定；重试成功后 `verdict` 为空，历史失败只留在 attempt 记录与统计。
- 错误码只允许从**可信通道**解析（SDK 结构化属性 / 约定的错误 envelope），**禁止**从任意显示文本解析——正文本身也可能包含 `{"code":1027}`。内部缺失 verdict 记 `CONTRACT_VIOLATION`，按 `UNKNOWN` 的有限策略处理，不重新扫描显示字符串、不尝试恢复 structured 身份。
- 序列化：错误与统计元数据用**显式 DTO / 编解码**，不依赖 dataclass 默认 JSON 形状，不把响应正文写入 checkpoint。

## 3. 全局正确性与费用约束

### 3.1 必须可测的不变量

1. 分析当前块时，所有上下文的直接及传递来源均早于当前块最早故事位置；整个重叠结果不得注入。
2. 已生成的快照是独立不可变值；异步写入不得改变其摘要内容或覆盖元数据。
3. 固定前缀原文、提取结果和策略，只追加/修改后卷数据，前卷候选、可见属性和 Prompt 不变。
4. 在固定来源、策略和模型返回/缓存结果下，完成顺序、重放及重启不改变最终业务状态；重新调用模型不保证同答案。时间戳、执行耗时等观测字段不参与等价比较。
5. rolling 的内容、输入结果版本和覆盖声明对应同一次提交；未知、失败、跳过不能冒充完整覆盖。
6. 未找到候选、原文核对不支持、材料不足、结论冲突、没有复检、调用失败和预算跳过是不同结果；缺失不是 false。
7. 任何候选应用前校验实体身份、版本与来源。模型置信度不能越过这些检查。
8. 已完成的章节结果不能因为 rolling/总结失败而丢失；费用、错误与任务状态均可恢复。
9. 无效候选不得抹掉其他候选仍成立的结论；真实来源失效或反证推翻可以使状态改变，旧结论必须留痕。
10. entity_id 不挪用到其他悬念/故事线；evidence_id 不随展示顺序重排；一条悬念的复述新增 occurrence，不自动回收。
11. 引用及支持段的最终偏移均由程序定位，必须映射回 hash 固定的规范原文；局部材料不足不伪装成全书核对通过。

### 3.2 模型调用预算

S0 记录实际调用基线，S2 定义统一 run budget，S7 接通预算执行。预算对整次运行及重启续跑累计生效，重启不能重置已用额度。

- 每次启动前计算：待分析块数、正常 rolling 计划、卷数、reconciliation 数、全书复检计划和已有缓存命中数。单列首次尝试与重试上限。
- 计算式为 `analysis + rolling_normal + volume_summary + reconciliation + recheck + style + final_report`；滚动归档等内部调用也必须计入，不能隐藏在一个外层任务名下。
- 正常顺序分析保留既有调用阶段，不因来源记录、稳定 ID 或视图构建增加新的模型阶段；批次触发边界固定，不按每次乱序完成多发 rolling 请求。
- 全书复检设置有限的 `recheck_max_calls` 和输入/输出预算。S0 用实际配置及样例量化现有上限，在 S7 启用默认值前固化对照证据；无法给出有限上限时不得以“无限制”自动运行。
- 将 OPEN+STALE 以及有未核对候选的实体纳入规划，但优先复用同输入的已完成任务。若扩大候选使预计请求超过默认预算，超额任务记 BUDGET_SKIPPED、不写成功标记；获得额外额度后可继续，不能永久视为否决。
- 原文语义核对属于 recheck 的正常工作，不能因 `semantic_review_max_calls = 0` 被关闭；该设置仅限制阶段外额外语义调用。`rolling_rebuild_max_calls = 0` 同样只约束额外重建，不承诺改造后与现有 recheck 等成本。
- 单批候选数不超过 `foreshadow_recheck_batch_size`（默认 40），它只是数量上限。`MAX_CONTEXT_CHARS` 约束单候选所附原文总量（初始建议 1200 码点，含埋设、引用及回收上下文），不会代替批次 Token 上限。
- 按 `RECHECK_BATCH_TOKEN_BUDGET` 装箱，累计 system、悬念、候选假设、来源标签、原文、实际附带的卷摘要与输出预留，并预留协议开销/安全余量。不超过模型上下文容量、单批预算和本次剩余额度中的最小值。
- 优先使用目标模型适用的 tokenizer/计数接口；无法精确计数时标明估算器、校准依据与余量。中文“字符数 / 1.6”最多作为待校准估计，不能作为通用上界或准确计费依据。
- 单条或批次无法满足输入预算时分批；单条仍放不下则记 BUDGET_SKIPPED、原因 MATERIAL_TOO_LARGE，不以硬截断后的片段继续声明证据充分。正常 recheck、失败尝试和恢复均计入 recheck 子预算及 run 总预算，不借用无限额的 analysis 配额。
- 用户可以保存常用预算，普通执行按保存值运行；只有需要超额时请求调整。界面展示预计范围、已用量和未覆盖任务，不要求用户理解内部实现。
- mock 预算测试与真实费用实验分开。真实 API 的效果、重试率和 Token 变化在获得预算授权后验证；没有验证时记录 NOT_VERIFIED。
- **确定性选择计划（R-5）**：候选排序、装箱与预算预留必须先冻结并持久化，再并发派发。排序键为「重要度降序 → 埋设故事位置升序 → 稳定来源/实体/候选逻辑键」；随机 UUID 仅在其已持久化并可复用时才可作为最后的 tie-breaker。批次边界不得由剩余运行预算临时改变；在固定重试预留规则下选择“能支付的最长批次前缀”，首个不能支付的批次即停止，不得跳过它去选后面更便宜的项。固定来源、策略、缓存快照、单项/单批容量与重试预留，仅提高运行预算时，入选任务集合只能扩展（前缀超集）；恢复时复用已持久化的排序键与装箱输入序列，不依赖遍历顺序或字典顺序。该取舍允许留下部分可用预算未使用，明确接受。

### 3.3 资源约束

“全史不删”是正确性要求，但不能据此认为进程内存有界。必须同时约束**字节与峰值**，而不只是对象数量：

- KB 缓存：条目数上限**与**估算字节预算（`KB_CACHE_BUDGET_MB`）；单项超预算**不缓存**，记 `SKIP_OVERSIZE` 并进入诊断输出
- KB 构建与复制的**并发上限**（`KB_BUILD_CONCURRENCY`），避免多份临时副本同时驻留
- 可观测峰值：主 KB、`results`、快照、临时复制**分别**记录估算字节
- 达到预算时的行为：安全小视图 / 按需读取 / **可恢复**的资源不足退出；不得无限扩张，也不得以删除磁盘全史换内存
- 资源准入必须发生在**昂贵构建/复制之前**——构建完成后再拒绝缓存挡不住峰值
- 失败或取消后释放预留，不跨运行累积；护栏参数不进入内容指纹，调高上限不使已成功产物失效

**计量与预留的硬断言对象**：

- **统一的估算字节账本**：主 KB、`results`、快照、在途副本**合并计入**同一个账本；不允许只给 KB 缓存设预算
- **在途预留**：进入昂贵构建前预扣，构建真正结束后才释放
- **并发许可**：构建与复制的许可数受 `KB_BUILD_CONCURRENCY` 约束，许可与预留一一对应
- 实际进程内存峰值仅作**基准观测**，不要求跨环境精确相等；可自动化的断言针对账本、预留与许可，不针对 RSS

**一个必须写清的边界**：`pipeline.py:691` 的快照构建走 `asyncio.to_thread`。取消等待方**不会**终止已启动的工作线程（已用本地探针确认）。因此预留必须在**工作线程真正结束**后释放，**不得**在外层 await 被取消时提前释放，否则账本会低估在途占用。

**其余资源各有归属阈值**：文件句柄、日志体积、临时目录都必须各自有上限与归属，**不得**用 KB 缓存测试替代。

“条目数有界”**不得**被表述为“字节有界”的证据。S9 保留大规模优化与基准，但若 S3 发现基础结构无法满足所定预算，必要的按需读取不得一律推迟到 S9。

3. 建立结果/依赖验证和提交时的 revision 检查。正文、分块或依赖不匹配时不得宣布“断点命中”。
4. 明确单书写入串行化：同一本书的分析写入与总结状态提交共享写入规则，允许并行生成候选，但不得覆盖彼此已提交的 manifest/账本。避免跨无关书籍的全局大锁。manifest revision 因无关任务推进而变化时，重读并重试元数据提交即可；只有实际依赖变化才判结果过期，不能重新调用模型。
5. 通用 JSON writer 检查返回值并原子替换；临时文件必须唯一且位于目标同目录。源结果持久化成功后，才能发布引用它的覆盖或任务成功状态。
6. 更新目录发现、队列恢复、书目 ID、手工目录注册与路径校验，防止其他服务绕过格式门禁。缺必需字段为格式错误，不调用旧默认值补全。
7. 原有测试中专门验证旧字段转换的断言在所属域切换时改为“明确拒绝”；仍有效的解析容错、来源完整性和数据安全断言保留。

**交付**：`docs/data-contract-vnext.md`、源/块/结果/账本/缓存例子、消费者清单和格式拒绝矩阵。新旧目录之间没有复制或转换脚本。

**门槛**：所有读入口拒绝不支持格式且不写入被拒目录；从原文创建新项目成功；更改块组成或正文使相关缓存失效。

### S3：安全快照、人物时序与有来源的知识库

**范围**：C-02、C-04、C-06、C-12、C-21，R1。

**主要文件**：memory_state、knowledge_base、模型、PromptBuilder/analyzer、viz/aggregate/导出/角色卡及对应前端消费者。

1. 逐块快照接口使用显式 `exclusive_before` 故事位置，筛选完整来源集合及其依赖。结果只要覆盖当前块任一章或后续章，整块排除；未知范围也排除。
2. 禁止逐章分析使用无上界全量 KB。汇总/导出可显式请求全量视图，但不能借该入口给逐章 Prompt 注入数据。
3. rolling 内容与覆盖元数据作为同一不可变值读取，在共同锁或原子对象替换下复制。旧快照不能共享 rolling dict；仅做 deepcopy 而分开读取元数据和内容仍不充分。
4. 人物状态维护逐人物的来源顺序与版本，只允许较新有效来源覆盖；迟到章节的新人物仍可加入。同章按明确来源位置排序，无法定位时以稳定字段顺序归约并保留不确定标记。
5. 增量合并、快照子集重建与最终落盘共用归约规则。recent_summaries、事实和时间线按来源排序选窗口，不以完成先后决定保留项。
6. `fact_records` 保存真实来源与验证状态；缺原文引用时保留 `UNVERIFIED`，不编造定位。重复/冲突事实可追溯至各自来源。
7. 图谱直接区分共现与语义关系，显式标示边类型。语义关系只接收有明确交互/关系证据的记录；需要模型补充时在既有章节提取调用内输出受限候选，不增加独立调用阶段，记录新增输出成本。
8. 全书存档与 Prompt 窗口分离。原计划 E5 的四项统一复核：源码已有 `AnalysisConfig.max_verified_facts`，当前用于 KB 裁剪，不能称为“配置项不存在”。新格式去掉事实落盘裁剪，Prompt 限额采用单独名称。
9. 本版关系、事实、主题和正文四类 Prompt 限额先作为有测试的内部设置，由统一构建入口传入；不新增四个用户按钮。公开设置扩展列为后续需求，现有文档不再宣称未接通的设置可调。

**门槛**：重叠块 `[1,2,3]` 对起始章 2 不可见；断号 `[1,5,9]` 也不能穿透；ch12(A新) 后 ch4(A旧、B首次) 保留 A 新状态并加入 B；同输入增量/重建等价；无互动不生成语义关系。

### S4：有序 rolling 与缺口恢复

**范围**：C-03 及 C-02 的覆盖部分。

**主要文件**：pipeline 的 rolling/预热/恢复/补跑路径、MemoryState、rolling 保存加载与测试。

1. 基于 manifest 的实际活动块顺序，分别维护 `completed_results`、`committed_result_ids`、`commit_cursor`、`committed_ranges`、`gaps`、`dirty_from` 与依赖指纹。
2. 连续性指实际输入序列中的相邻块，不是自然章号连续。分析从第 100 章开始时，覆盖声明也从该范围开始，不能称为全文前缀。
3. 分析仍可并发；rolling 提交按故事顺序。批次边界固定，只有完整批次前缀可消费；收尾策略单独固定，不能按每次完成顺序随意拼不同输入。
4. `PENDING_RETRY` 暂停推进；`TERMINAL_SKIPPED` 可按策略越过，但保留 gap 并标 `PARTIAL`。commit cursor 的推进不等于完整前缀增长。
5. `LATE_REPAIRED` 或已提交结果版本变化使依赖摘要变脏。默认停止使用受影响摘要，继续保存章节结果；用户启用重建预算后，从最近仍有效的安全检查点按固定批次重建。
6. 正常顺序路径不增加摘要阶段或重复消费同一结果。首次早期摘要、增量更新和 momentum 归档都必须共享正确覆盖元数据与预算统计。
7. 未提交的新内容可以等待；使用之前的安全前缀或安全近章 KB 降级，明确其覆盖范围。没有安全摘要时不注入，不回退到旧格式文本。
8. LLM 调用在锁外进行，提交前核对依赖版本。统一锁序，持有线程锁时不得 await；临界区只做快照/引用切换。内容与元数据一次发布；来源结果先持久化，摘要成功但写入失败时不推进已提交水位。
9. 覆盖预热、全量已完成早退、补跑收尾、取消、模型失败、写盘失败与重启。摘要失败不影响成功章节的最终保存。

**门槛**：100/102 已完成而 101 缺失时不宣称完整覆盖；补回后标为待提交或待重建；10 种完成顺序在固定 mock 输出下得到同一输入分组、覆盖和状态；崩溃恢复不能出现摘要/覆盖版本错配。

### S5：稳定伏笔实体与截至当前卷的候选视图

**范围**：C-27 的候选构造，R2/R3。

**主要文件**：text_utils 去重、foreshadow_ledger、新实体登记、final_summary catalog/prompt、API/DTO 与测试。

1. 落实第 2.3 节身份规则。先处理原始出现记录与实体登记，再生成展示列表；不得把排序序号写成权威 ID。
2. 前卷输入从原始出现记录中先筛出全部来源与上下文依赖均不晚于截止位置的记录，再去重/汇总可见属性，再应用类型/重要度过滤、评分与数量/Token 上限。只有块级归属且范围跨越截止点时整条排除，不能只凭 first_seen 放入。
3. `type`、`importance`、`confidence`、出现次数、跨度、last_seen、代表描述、证据列表都由该视图计算。先按全书排名截断后再删未来章号的路径删除。
4. 新增未来记录可以指向既有实体，但不能重写历史实体 ID、代表描述或既有成员归属。未来合并建议不影响前卷视图；显式应用合并属于策略/实体版本变化，单独使依赖失效。
5. 当前轮候选和各卷 Prompt 在任务生成时冻结。并行任务不读取正在变化的账本状态或后卷调和结果来增删前卷候选；既有账本中的后卷 AUTO_RESOLVED 也不能过滤前卷输入。前卷候选由截至当时的出现记录视图决定，全书最终状态仅用于归约和报告。
6. 使用固定输入的模型候选与核对结果，按 `(卷起始位置, batch_idx, candidate_id)` 提交，再对全部当前有效候选归约。失败卷显式保留任务状态，不作为“本卷没有回收”；重复重放不创建新身份或覆盖更高输入版本。
7. S5 同时验证两种去重语义：同一悬念再次被提起应归同一实体并新增 occurrence；同一对象的不同悬念（“谁藏了王冠”与“王冠藏在哪里”）不能仅凭相似度合并。一项答案不能自动关闭另一项悬念。
8. **最小只读诊断输出（D-03）**：同批在已有只读 API 或一个诊断命令中输出——数据格式版本、来源 revision、`occurrence`/`entity`/`candidate` 计数、`resolution_state` 分布、`recheck_status`、以及覆盖与跳过原因（分 `reason_code`）。**不新建功能页、不调模型、不写文件**；字段全部取自同一 revision，与其他读接口同源、不二次计算。未运行总结时按 T43 显示 `NOT_RUN`，不得以空候选集冒充“已核对”。该输出使 S5 成为可验收的中间里程碑：能证明来源、实体身份与截至视图成立，但完整自动回收仍需 S6/S7。

**门槛**：早期补跑、筛选变化后已有实体不串号；固定 1–10 章，只追加/修改 11 章以后的来源，前 10 章候选集合和 Prompt 不变；多种完成顺序与恢复重放得到相同业务结果；T40/T41 分别验证不同悬念不误合并、相同悬念的复述正确归属。

### S6：原文证据与全自动裁决

**范围**：C-05、C-10，R4。

**主要文件**：章节提取模型/Prompt、source_ref/证据定位、final_summary 调和与原文 recheck、ledger 归约器、只读 foreshadow API、Timeline 证据组件及测试。

**接口 B 固定分工**：reconciliation 从本卷摘要与截至当前卷的悬念提出候选，并说出候选答案；recheck 读取原悬念、候选答案、埋设原文及回收上下文，核对答案与反证。候选答案必须标为“待核对假设（未经核实）”，不能作为已经成立的结论。recheck 不接收第一阶段的自评置信度、解释或推测事件时间；核对所必需的原文时序与时间限定不删除。

1. **引用定位**：模型只提供 `chapter_id + quote_hint`，程序从固定 content_hash 的规范原文定位；偏移、原文 quote 与 evidence_id 均由程序生成。唯一命中标为 EVIDENCE_LOCATED；未命中或仍有多处歧义记 INVALID，不为同一候选循环询问模型。
2. **有界本地重定位**：可执行一次固定版本的定位预处理，但不能把扩大窗口或删空白本身当成消除多处匹配的证据。有额外可信范围/上下文锚点才可排除匹配；仍歧义就退出。规范化匹配若使用空白、全半角/引号变体，必须有到规范原文的偏移映射，最终保存 `quote = canonical_text[start:end]` 并逐字复验，模型原 hint 单独保留。禁止删除否定词、跨段拼接或任意选择一个匹配。
3. **证据身份与顺序**：对 `[book_id, chapter_id, content_hash, start, end]` 作固定序列化并计算 SHA-256，存储完整锚点及完整哈希作为 evidence_id；12 位缩写只用于展示，不作唯一键。新增早期证据不重排 ID。先后比较使用 manifest 中的 `(章节故事顺序, 章内码点偏移)`，不能直接比较不同章节的偏移。
4. **上下文取材**：包含 quote 所在完整句段及说话者、引语前缀，按版本化规则扩展前后文，直到满足 PRE_CHARS/POST_CHARS 目标或自然边界。记录 `context_start/end`、原文 hash、`chars_used`、`context_truncated` 和原因、实际核对范围。到达章节真实边界不等于预算截断；硬上限导致句段不完整、材料遗漏或来源缺失时标记不足。首版对硬预算截断不设“支持段自足”放行例外，不能让模型自行越过输入完整性门槛。
5. **recheck 输出**：对每个允许的 candidate_id 返回 verdict、answer、支持短引文/已有 evidence_id、反证核对记录和材料不足原因。程序校验所有 ID 均来自该任务，支持及反证引文均在提供的来源范围内，并生成最终 supporting_span；模型不计算支持段偏移。没有原文引用的自由文本解释不构成证据。
6. **统一反证核对**：所有重要度均执行。记录 `performed`、检查过的 evidence/range 和反证引用；`counter_evidence = null` 不能单独放行。SUPPORTED 还要求反证核对已执行、没有已报告反证、没有材料不足/硬截断、支持段定位有效。模型的 performed 与语义支持仍是待评测的推断，不是已穷尽全书反证的程序证明。
7. **纯程序裁决**：先验证来源/实体 ID/版本/范围/顺序；可确定错误记 INVALID/具体 reason_code，过期输入不提交新快照。形式 ID 正确但原文实际回答另一悬念的情况，由 recheck 做语义判断，不能声称程序能直接识别。结构与输入有效后，SUPPORTED 且所有门禁通过才记候选 SUPPORTED；DIFFERENT_ANSWER/CONTRADICTED 记 CONFLICT；INSUFFICIENT 或反证核对/材料条件不足记 INSUFFICIENT。不比较自由文本答案，不增加裁决器内部模型调用。未知枚举/不合法响应走有界解析失败路径，不能缓存成语义通过。
8. **实体归约与历史**：按 §2.3 对全部当前有效候选归约；新 INVALID 不覆盖其他支持结果。原支持候选因新来源/反证被推翻时，先使对应旧裁决失效/被取代，再归约，保留 superseded_by/superseded_at。更新只读报告和缓存依赖，不要求用户收尾。
9. **同章与近期状态**：允许同卷/同块及同章先埋后收；位置不明不自动通过。删除“同一批次不可能回收”的提示。STALE 仍按真实故事顺序距离计算，默认展示阈值 200 章，不改变解决状态。
10. **只读呈现**：证据展开组件显示原文、上下文高亮、章节跳转、裁决与任务结果。列表/报告区分“自动判定已回收”“存在候选但证据不足/冲突”“尚无有效候选”“本次未核对”，不存在操作按钮或人工处理入口。Unicode 高亮使用后端码点约定，覆盖 emoji/非 BMP 汉字。
11. **复检覆盖必须计数披露**：每次全书复检结束时写入结构化汇总并进入报告与只读 API——候选总数、提交核对数、定位成功数、`SUPPORTED`、`INSUFFICIENT`、`CONFLICT`、`INVALID`（分 reason_code）、`STALE`、未核对数及原因、实际调用数与花费。汇总缺失时该次复检不得标记为完成。禁止沿用现有 `无活跃伏笔，跳过全书复检` 式的静默返回：候选集为空也必须记录一次 `COMPLETED` 且计数为 0，使“本次没有候选”与“本次没有运行”在产物中可区分。
12. **未运行总结的书必须显式标注未复检**：账本需持久化 `recheck_status`（`NOT_RUN` / `RUNNING` / `COMPLETED` / `PARTIAL` / `STOPPED`）与对应 task 记录。仅完成逐章分析、未运行总结（含 `auto_summary` 关闭、总结被取消或停在阶段 1）时，状态必须为 `NOT_RUN` 或 `STOPPED`，且只读 API、Timeline 与报告一律显示“未复检”，不得显示为“已核对”“已完成”或“无候选”。阶段 1 只允许产出候选，不得在未复检的情况下对外呈现“自动判定已回收”。

模型侧 recheck 返回示例（verdict 取固定四枚举；最终 supporting_span 由程序补充）：

```json
{
  "candidate_id": "candidate-from-this-task",
  "evidence_id": "evidence-from-this-task",
  "verdict": "SUPPORTED",
  "supporting_quote": "那顶王冠早已熔成金锭",
  "answer": "王冠已被熔毁",
  "counter_search": {
    "performed": true,
    "checked_evidence_ids": ["evidence-from-this-task"],
    "counter_quotes": []
  },
  "material_insufficient_reason": null
}
```

**门槛**：无用户操作即可完成候选、定位、原文核对、裁决、状态归约与报告；引用错误/过期/顺序错误不能通过；新垃圾候选不降级独立有效结论；不确定结果完成后可缓存，恢复幂等。同一物件不同悬念、同章顺序与原文时态由相应测试覆盖。语义准确性由研发评测验证，不以纯函数测试替代。每次复检必须留下可核对的覆盖计数；未运行总结的书必须在产物中显示“未复检”，而非任何形式的“已完成”。

### S7：复检任务缓存、确定性状态重放与预算

**范围**：C-11、C-27 的恢复部分，R5。

**主要文件**：final_summary、checkpoint/任务记录、ledger、summary 服务/配置/前端进度与测试。

1. 卷摘要、reconciliation 和全书 recheck 的任务完成记录均为必需。阶段 2 不能再通过“已回收”状态充当缓存。
2. 在第 2.4 节基础上生成任务键。reconciliation 依赖本卷摘要与当时可见悬念；recheck 依赖原悬念/实体版本、候选答案、实际提供的摘要/原文范围与 hash、定位/窗口/Prompt/模型/策略版本。只对单个引用的 hash 相同不能证明整个核对任务输入相同。
3. 规划覆盖 OPEN+STALE 及有候选的实体，先复用同输入的成功任务，再对未核对候选按预算分批。没有回收候选时记 NO_CANDIDATE，不能虚构回收窗口或记为原文复检通过；新增候选发现若需要额外模型调用，单独计量并受预算约束。原文核对材料不足、冲突和有效输入的 INVALID 同样是可复用结果，不进入自动循环。
4. 所有候选及原文核对结果收集后按稳定顺序提交，再归约；或使用可证明等价的有序提交。保存应用键、当前裁决版本和实体 revision，缓存重放复用已有 candidate_id，不重复追加事件。输入变化允许状态改变，历史结论保留，不允许身份挪用。
5. 请求前原子预留调用预算，失败尝试也扣实际额度；释放未开始的预留，重启重建使用量。到达调用/Token 上限时停止派发新增任务，保存可续跑状态和跳过清单。
6. 输入改变只使依赖项失效；一个源码依赖被许多后续阶段实际使用时，可以扩大失效范围，但必须给出具体依赖原因和重算清单。
7. 汇总本次新调用、缓存复用、无回收成功、失败、取消、预算跳过及实际费用；不能把“未执行”显示成“复检完成”。
8. 风格提取与最终长报告的完整缓存列为条件优化；先测重复费用，复用同一任务键机制，不阻断本批必需的复检缓存。
9. BUDGET_SKIPPED、FAILED、CANCELLED 只保存未完成任务，不写成功标记；获得预算或重新运行后按配置继续，不能每次恢复先自动重试已完成的 INSUFFICIENT/CONFLICT。STALE_SOURCE 退出当前快照，下一稳定输入使用新任务键，不能把旧 hash 的失败结果重新当作新输入成功缓存。

**门槛**：同输入重复总结不新增卷摘要/调和/复检调用；中断后只补未成功任务；证据不足/冲突/有效输入的无效候选可复用；预算提高后原未执行任务能继续；相关来源变化准确失效；候选与裁决历史跨重启不丢。

### S8：熔断、写入一致性与基本交互保护

**范围**：C-07、C-09、C-16、C-18、C-19、C-20。

以下子项可独立提前，但需满足各自依赖，并避免并发修改相同文件。

**S8a 账户级熔断（依赖 S1）**

- 首个可信 ACCOUNT_GLOBAL 判定即可停止同一端点/凭据作用域的新请求派发；不等待多个块把已确定的欠费重复验证。
- 每次获得并发槽后、每次重试发 HTTP 前检查运行级熔断。已发请求有界收尾并保存结果与费用，等待任务保留 BLOCKED 状态。
- REQUEST_LOCAL 不整场停机；429/5xx 按有界退避/限流处理。作用域不明不能凭字符串升级为账户熔断。余额/凭据修复后用户可续跑。
- 测试确认熔断后新增派发为 0；额外已发请求不超过当时在飞数量。rolling/summary 使用同一账户时也需消费该运行范围内的熔断，不引入跨无关账号的全局锁。

**S8b 原子保存和产物组发布（依赖 S2）**

- 所有生产 JSON 使用检查失败的原子 writer；不得在保存失败时显示成功。
- 聚合的多份 JSON 使用唯一 generation 目录写齐、校验后原子更新 manifest 指针。读 API 和 Excel/文档导出先固定 generation，再读取同一组文件。
- Windows 下不依赖“替换非空目录”的不可靠假设；测试文件占用、替换失败、进程中断和双读写。旧 generation 只有在不再引用且符合保留策略时才清理。
- 关键账本和决策提交同样避免半组状态；可使用一个包含决策与当前状态的原子快照，或有明确恢复规则的 journal，不能只宣称逐文件原子便等于事务。

**S8c 用户文件操作（可在 S0 后提前）**

- 临时目录端到端覆盖新工作区创建、归档、删除、移动、覆盖、重命名，测试中文/空格、冲突、跨盘失败、权限拒绝、中断及恢复。
- 校验解析后的目标位于操作明确授权的根内；覆盖目录穿越、符号链接/重解析点。移动失败不提前删除原目录或修改队列为成功。

**S8d 页面安全与并发设置（可独立提前）**

- 所有 LLM/用户内容进入 v-html 前，在最后渲染边界经过成熟 sanitizer；实施时核实官方文档并锁依赖版本。覆盖恶意协议、事件属性、实体编码、嵌套 HTML 和正常表格/链接。
- 设置改为字段白名单 PATCH + 预期 revision，在服务端同一临界区比较并写入。两页冲突返回 409；前端保留用户修改并提示重载/合并，禁止自动提交旧全量快照。
- 轮询加入超时、取消、同页单飞、离页停止及响应序号检查，保留 WS/seq 语义。慢接口 15 秒不能使请求无限积累，旧书响应不能覆盖新书页面。

**门槛**：费用和账户停止范围有界、无半写/混代读取、文件操作失败不丢源数据、渲染无脚本执行、设置无静默覆盖、轮询可终止。

### S9：规模治理、摘要压缩与语义质量实验

**范围**：C-13、C-14、C-15、C-26；C-21 已由 S3 明确落地。

1. 用新格式合成大书测内存、快照耗时、Prompt 构建、索引大小与图谱边数量。先限制注入视图、使用来源索引与稀疏显示；确有证据再做磁盘分页或冷存储，保留完整存档。
2. 记录 system、完整故事历史、短期上下文、正文和输出的 Token；使用模型实际 tokenizer/usage，无法精确计算时注明估算器和误差，不用字符比例充当注意力指标。
3. A/B/C 使用同模型、相同采样策略和源章节，至少 3 次重复：A 为既有组织方式；B 去重历史并按人物/来源检索；C 在 B 上精简输出任务。除来源/证据必需字段外的 Prompt 精简须先实验，不默认拆多个 Agent。
4. 研发阶段用 50–100 章独立标注集测事实准确率/召回、人物状态冲突、候选误报/漏报、AUTO_RESOLVED 误报/覆盖率、关系虚假边、可读性、Token、耗时及重试率，报告原始样本数、分母及差异区间。标注不进入产品运行流程，不要求用户处理每条结果。
5. 对相同原文/候选范围做随机顺序、候选答案可见与隐藏的配对评测，覆盖通过、未通过及冲突样本，估计接口 B 的锚定风险。与独立标签比较准确率和方向性变化，重复采样区分模型波动；仅两次结果的一致率不能单独估计锚定偏差。该额外调用有独立研发预算，不修改产品任务状态。所有重要度统一证据标准，不用低重要度放宽通过条件来改善覆盖数字。
6. 先测实际卷摘要压缩触发率和受影响信息；若需要替换字符截断，保留关键事件、未决线索及可回查证据索引，显示省略范围。长度合规不能作为完整性证明。
7. 所有付费 A/B 有独立预算和授权；结论不明确时不启用可选 Prompt 精简。基础来源/时序/证据修复不依赖实验显示文学质量提升才能交付。
8. 对 pipeline、summary、style、location 的真实峰值做观测。仅在确认同账号额度冲突时增加会话/账号范围的预算协调；无证据时 C-26 记为 DEFER，不阻断核心版本。

**门槛**：完整存档不因裁剪丢失，性能结果可重现；可选质量优化有人工答案集和费用证据，否则明确 DEFER。

## 5. 确定性测试矩阵

测试应调用生产入口，不复制待测归约或状态机实现。下列 ID 是验收项，实施时落入相关单元、集成或端到端测试文件。

| T42 | 预算不足后提高额度，单条过大、批次装箱与估算 | BUDGET_SKIPPED 不写成功标记；同 task_key 可续跑；候选数与完整请求 Token 分别限额；不以固定中文比例保证上界。**追加**：固定来源、策略、缓存快照、单项/单批容量与重试预留，仅提高运行预算时，**入选任务集合**只能扩展（前缀超集）；不要求实际成功集合也单调——新增入选任务可能失败，但已 `SUCCEEDED` 项不得重跑或回退。恢复时复用已持久化的排序键与装箱输入序列，不依赖遍历顺序或字典顺序 |
| T43 | 仅完成逐章分析未运行总结；总结被取消或停在中途；`auto_summary` 关闭 | 账本 `recheck_status` 为 `NOT_RUN`/`STOPPED`；只读 API 与原样报告显示“未复检”；不得显示为已核对、已完成或无候选；未复检时对外不出现“自动判定已回收” |
| T44 | 候选集为空、候选全部 INVALID、候选全部 STALE | 复检仍记 `COMPLETED` 并写覆盖计数（候选 0 / 有效 0 / 各 reason_code 与跳过原因）；报告显示“本次无有效候选”；不得沿用静默跳过路径，也不得把 0 条显示成“复检完成”而无原因 |
| T45 | LLM 错误判定全程逐跳传递（提供者→attempt→终结结果→chat_auto→analyzer→queue/runner→checkpoint→API/DTO→UI） | 全部枚举值逐跳不丢真、不降级为布尔或中文文案；缺失或未知判定不得默认 SUCCESS；**判定沿革**：同一错误逐层包装保留原始原因；不同 attempt 各自留记录、终态取**导致停止的那次**判定；重试成功后 `verdict` 为空、历史失败只留在 attempt 记录与统计中；**序列用例**：① `429 → AUTH` 终态须为 AUTH，不得把限流传给外层而重跑认证失败的请求；② 失败→成功；③ 有 usage 的失败→无 usage 的断连（后者 `usage_status=UNKNOWN`、`tokens=None`，不得写成 0，不得沿用前次计数）；`CANCELLED`/`SKIPPED` 不计入模型失败统计；API 与 UI 展示逐字一致，不可映射值原样透出。前置夹具：异常携带可信结构化码而其显示字符串不含该码——用于证明判定来自字段贯通而非文本扫描（**不要求生产代码删除数字**）。已知消耗与未知 usage 分别断言。**自动化方式**：SDK mock 依次返回结构化 429 与 AUTH（两者显示字符串均不含错误码），替换等待函数；断言等待参数、尝试次数为 2、终态为 AUTH、外层不补跑，以及 DTO 往返后字段不丢失 |
| T46 | 只读诊断输出的完整性 | 不调模型、不写文件；字段全部取自同一 revision；候选维度守恒式 `candidates_total = supported + insufficient + conflict + invalid + stale + not_checked`，不重不漏；过程计数（`submitted`/`evidence_located`/`llm_calls`/`cost`）单独列出、不参与该等式；`reason_code` 枚举闭合，未知落 `OTHER` 且保留原值；字段 key 与顺序稳定可机读，与账本、API 同源不二次计算；输出脱敏（绝对路径、凭据、超限原文）；诊断自身失败不得改变业务状态或把报告刷成“已完成”；合法零值、字段缺失、`NOT_RUN` 三者可分辨 |
| T47 | 资源护栏 | 并发、内存、句柄、日志体积、临时目录均有显式上限，超限排队或拒绝而非崩溃；**多个单项均未超限但累计超预算**时必须被挡住；资源准入发生在昂贵构建/复制**之前**；失败或取消后释放预留；资源耗尽独立归因 `RESOURCE_EXHAUSTED`，不混入 `FAILED` 或模型失败统计；护栏参数不进入内容指纹，调高上限不使已成功产物失效；磁盘满 / 权限拒绝 / 限额超限三类可区分；不以删除磁盘全史换内存。**自动化方式**：预算设 100、并发上限设 2，两个任务各预留 60；用屏障保持第一个在途，断言第二个在**构建前**排队或拒绝；取消第一个等待方后，预留仍保持到工作线程真正结束，再验证后续任务可继续 |

## 8. 最终完成定义

新版本可从原文创建独立项目；所有读写入口只接受本版本契约。章节、来源、实体、候选、决策和费用可以追溯；改变起点/正文或补跑不会混入错误结果；当前章和未来知识不能进入前序分析；rolling 不用不完整覆盖冒充完整。

人物状态在乱序与恢复后稳定，共现不虚构语义关系；未解决与近期未提及互不混淆。原文证据、接口 B 核对、程序准入与实体归约形成全自动流程，输出自动判定及可查原文，不保证零误判。用户只读查看，不承担逐条裁决；证据不足、冲突、本次未核对都可正常结束。

候选处理完成与实体状态相互独立；同输入成功结果可复用，预算跳过/失败/取消可有界续跑，来源变化准确失效，旧结论留痕，垃圾候选不能抹掉其他有效支撑。文件保存、账户熔断、渲染、设置和轮询通过对应门禁。

必需批次有自动测试和新格式端到端证据；桌面发布有真实 Windows 验证。标注、接口 B 锚定盲测与可选 Prompt 优化属于研发验证，独立预算，不进入用户操作流程。旧产物读取、字段转换、迁移报告、旧 API/状态投影均不属于完成条件。
